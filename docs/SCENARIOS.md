# 使用场景拆解

## 场景 1：多个账号不串号

用户有多个 Claude / Codex 账号，希望同时登录或快速切换，但不希望登录态互相覆盖。

解决方式：

- 每个账号槽位绑定独立本地 profile 目录
- 点击「打开账号」时用该目录启动官方 App
- 管理器不保存密码，登录仍发生在官方 App

## 场景 2：找回某个旧会话

用户记得某个任务做过，但不知道在哪个账号、哪个会话里。

解决方式：

- 按账号切换，或切到「全部账号」统一查看
- 中间表格可在精简 / 详细视图间切换，点击任一属性表头排序
- 搜索标题、项目路径或线程 ID
- 右侧显示会话文件和项目目录

## 场景 3：把旧会话交给新会话继续

用户希望把一个 Claude/Codex 旧会话的信息交给新会话，让新会话理解上下文。

解决方式：

- 勾选一个或多个会话；切换账号后已勾选项仍保留，也可直接在「全部账号」范围跨账号选择
- 在交接清单中用上移 / 下移规划优先级
- 在「交接资料」里确认该会话已有的规划文件、任务清单或会话内计划；明确关联默认勾选，时间关联候选默认关闭
- 点击「复制交接信息」
- 粘贴到新 Claude / Codex 会话

复制内容按清单顺序合并，包含元信息（应用、账号槽位、账号、标题、新建时间、活跃时间、项目目录、会话文件和线程 ID）以及用户最终勾选的交接资料正文。完整聊天内容始终不复制；交接资料有单文件、单会话和整次复制上限。

## 场景 4：Windows 使用

Windows 用户也需要同样的账号槽位和会话索引能力。

解决方式：

- 自动识别传统 `%APPDATA%/<App>` 与 Store/MSIX 的 `LocalCache/Roaming/<App>` 实际目录
- Codex 会话目录使用 `%USERPROFILE%/.codex`
- 新增槽位放在 `%USERPROFILE%/.agentdesk/profiles`，避开 AppData 虚拟化
- 同时识别 Store 执行别名、MSIX 当前包、传统安装与旧版 `app-*` 更新目录
- 会话文件失效时回退到可访问的上级目录，不让 Explorer 弹“位置不可用”
- 旧 AppData 独立槽位支持一键复制迁移，旧目录保留
- Windows 版本提供 portable `.exe`

## 场景 5：集中检查并维护本机 Agent 工具

用户同时安装了多个桌面 App 和终端 Agent，希望知道哪些缺失、哪些可更新，并快速打开。

解决方式：

- 从顶栏「工具」打开维护台，一次扫描桌面 App、CLI、版本和实际安装来源
- 点击「检查全部」刷新远端最新版本；缺失项目用「获取」打开官方页面
- 点击任一项目的「打开」：桌面 App 使用对应账号槽位启动，CLI 在新的系统终端中打开
- 可自动维护的 CLI 使用原来的 npm / Homebrew / uv / 自身更新器；可单项更新，也可原生确认后一键批量更新
- 桌面 App 或来源不明、不可写的 CLI 不强行替换，只打开官方更新入口

版本查询和更新命令都由主进程固定目录生成。界面不能提交任意命令、可执行文件或下载 URL，也不会调用 `sudo`。
