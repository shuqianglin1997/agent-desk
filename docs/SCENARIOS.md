# 使用场景

## 1. 多个账号不串号

用户有工作、个人或备用账号，希望保留各自登录态。

- 每个槽位绑定独立 profile 与 session root。
- “打开账号”使用该槽位启动受支持的官方 App。
- AgentDesk 不保存密码，登录仍由官方 App 完成。

## 2. 找回旧会话

用户记得某个任务做过，但不知道在哪个账号或客户端。

- 设备 Lens 选择“全部设备”，会话范围选择“全部 Agent”统一浏览；需要时也可收敛到某台设备或当前 Agent。
- 搜索标题、项目路径、账号或线程 ID。
- 在精简/详细视图间切换，点击表头排序。
- Compact 模式在左侧会话面板内单屏显示；只有详细模式允许明确的水平滚动。
- 选中一条记录查看来源、时间、状态、模型和项目。

### 上下文压缩后的同一会话

- Codex 的 `compacted`、`context_compacted` 只是同一会话内部检查点。
- guardian、subagent 等内部 rollout 不进入默认列表。
- 即使内部记录的父文件暂时不可见，也不会把内部记录提升成新会话或新项目。
- active 与 archived 中同一个根 thread 按逻辑会话 ID 折叠，不按物理 JSONL 文件计数。

## 3. 复制一个或多个会话的定位

用户找到目标会话后，需要继续在原工具周边工作。

- 单击一行只聚焦右侧详情；没有显式勾选时，单会话动作使用该焦点。
- 用复选框明确加入一个或多个批量动作项；搜索隐藏的已勾选项仍保留并显示数量，可一键清空。
- 聚焦单条时，复制、发送、打开和导出集中在右下详情的同一个底部动作坞；显式勾选后，该动作坞原位切为批量摘要、取消、复制和发送。
- Footer 只显示全局状态、今日完成数、陪伴分钟和提醒总开关；庭院画面里没有小账本或提醒条。
- “复制会话信息”只输出每条会话的路径和坐标。
- 同一逻辑会话存在多个副本时，必须先选择确切来源；未解决前复制、发送、定位和导出都不会静默猜测。
- 在 Finder / Explorer 中定位来源文件。
- 对提供可靠解析器的来源导出 Markdown。
- 回到官方 App 或 CLI 中自行继续工作。

AgentDesk 不替用户补充说明，不合并多个会话，也不会把历史记录加入执行队列。需要交接整项工作时，用户可以从聚焦会话另行创建 TaskPackage，并亲自填写阶段检查点。

## 4. Windows 使用

- 自动识别传统 `%APPDATA%/<App>` 与 Store/MSIX 的真实漫游目录。
- Codex 默认会话目录使用 `%USERPROFILE%/.codex`。
- 新增隔离槽位放在 `%USERPROFILE%/.agentdesk/profiles`，避开 AppData 虚拟化。
- 同时识别 Store 别名、MSIX 当前包、传统安装和旧版更新目录。
- 来源文件失效时回退到可访问的上级目录。
- 旧 AppData 独立槽位可复制迁移，原目录保留。

详见 [WINDOWS.md](WINDOWS.md)。

## 5. 集中检查本机工具

用户安装了多个桌面 App 与 CLI，希望快速知道哪些缺失或可更新。

- 从顶栏“工具”打开独立弹窗，扫描安装、版本和来源；关闭后仍回到原会话详情和选择状态。
- 缺失项目用“获取”打开官方页面。
- 桌面 App 按账号槽位打开；CLI 在新的系统终端中打开。
- 可维护的 CLI 沿用原 npm / Homebrew / uv / 自身更新器。
- 单项或批量更新均由用户明确触发；批量更新需要原生确认。
- 来源不明、不可写或没有稳定更新方式时不强行替换。

版本请求、命令和 URL 均由主进程固定目录生成；界面不能提交任意命令，也不会调用 `sudo`。

## 6. 查看账号状态

- Codex 槽位展示官方本机 RPC 返回的额度周期。
- 不支持的客户端显示 unsupported。
- 活动时间驱动会话排序、关注提示与庭院猫状态。
- 路径、额度等持久待处理事项进入 Header 的“活动”弹窗，不用庭院气泡长期遮挡 Agent。
- 当前运行位置即使只有一个也保持可见；路径、权限或启动异常在“管理 Agent”的“当前运行位置”分区查看。
- 庭院的时间和天气只由一个“场景 · 当前时间 / 天气”按钮打开 Top Layer Popover 调整，不在画面上常驻多组按钮。

## 7. 建立自己的设备网

- **当前实现：** 全新用户可在“创建第一个 Agent”时一并建立仅限本机的目录与设备身份；顶栏“设备”提供同一事务的高级入口和后续设备管理。设备弹窗保持独立，只有选择“查看会话”或“查看屏幕”时才关闭并执行对应导航。
- 本机生成受系统密钥保护的设备身份，现有身份组迁移为全局 Agent，Profile 保持为本机运行位置。
- 已加入设备生成一次性配对码；另一台电脑粘贴后优先通过临时局域网入口会合，局域网不可达时可使用邀请码中签名的 HTTPS 信令地址。
- 两端完成设备证书、指纹和邀请码 proof 验证后才加入同一 Mesh；账号密码、Cookie、Token 和 Root 私钥不会传输。
- 每台远端设备都可以独立改权限、断开或撤销删除，不存在“必须保留一台远端设备”。
- 本机可以完整退出并重置 Mesh；重置不删除账号槽位、官方登录或会话。

**当前 `0.10.1-preview.1`：** 普通首次使用已经从“创建第一个 Agent”开始。缺失 `profiles.json` 时先建立真实空目录；用户提交后，Main 在一个可恢复事务中建立本机 Agent、Blueprint、设备身份并进入 Provisioning。该事务不开放监听、不发布在线租约，也不连接远端；检测到既有 Profile 时先显示可选择的无损迁移预览。完成状态只在用户真正看过完成页后按向导版本保存，应用重启可以从已有本机事实恢复。

“添加设备”也已按“确认身份 → 建立信任 → 连接设备 → 同步目录与库存 → 可以使用”组织。加入端先在 Main 验证邀请并让用户核对设备与安全指纹；邀请端也必须在签发成员证书前确认加入设备。成员信任、认证连接、目录落库和首份库存落库分别投影，关闭再开会从持久事实恢复，而不会把配对成功写成已经可用。“接收连接 30 分钟”只留在高级恢复。完整物理双机向导、全应用重启后的双端恢复、公网与跨平台矩阵仍待验收。

## 8. 管理多台电脑上的全部 Agent

- Agent 是长期员工，不由现有 Profile 反推生命周期；即使没有账号绑定或任何运行位置，也会在每个工作环境中继续显示。
- 当前环境没有 Slot 时，主动作进入可恢复的“首次准备并打开”；系统只创建 AgentDesk 受管 staging 与白名单配置，官方安装、登录、验证码和系统权限仍在目标设备由人完成，验证成功后才提交正式 Slot/Deployment。
- 同一个实际登录可出现在多台设备，同一设备也可有多个账号；强账号标识相同时只增加运行位置，不复制 Agent 或猫。
- 顶栏“全部设备/某台设备”只改变设备视角，会话区“当前 Agent/全部 Agent”保持独立，两者组合覆盖全局和局部查看。
- “新增”先明确选择新 Agent、已有 Agent 的另一账号绑定或本机新运行位置；无可靠账号 ID 时也必须显式选择归属，不按名称猜测。
- Agent 全局信息、AccountBinding 和本机 AgentSlot 分开管理；合并 Agent、拆分绑定以及移除运行位置/登录账号/整个 Agent 都显示影响范围。
- 设备离线时保留最后一次库存快照并明确标记；来源设备只写自己的 Slot 与会话副本。
- 全局目录与设备库存独立：现代连接只在签名 feature 协商后同步 Agent/Binding/Blueprint/tombstone，inventory 不能借只读权限改绑、删除或裁剪员工；旧端安全降级为 inventory-only。
- 所有账号、运行位置、Agent 和远端设备都允许删除到零；离线旧库存不能让已删除 Agent 复活，也不会补回 Claude、Kimi 默认项。
- 已就绪远端只接受固定 `profile.launch`，未就绪远端只接受受限 `agent.prepare`；目标端确认期间若撤权、断连或连接被替换，迟到允许不会创建准备任务。

## 9. 把会话信息发到另一台设备

- 用户先在会话表单选或多选；主按钮“复制会话信息”始终只生成路径和坐标。
- 紧邻的次级按钮“发送到设备”只提交稳定会话 ID、副本 ID 和目标设备 ID，Main 会重新解析来源。
- 在线目标通过认证 WebRTC 收到端到端加密 SessionPointer；离线目标进入发送端本机密文队列，双方再次在线后重试。
- 目标项目路径不从来源绝对路径直接执行；用户在目标端通过系统目录选择器确认本机项目根。
- 收到的会话信息继续使用相同的“路径 + 坐标”格式，不生成摘要、下一步或交接话术。

## 10. 把整项工作交给另一个 Agent、设备或人

这类场景需要对方取得的不只是位置，而是一份在同一时刻对齐的会话、代码现场和责任说明。

- 用户聚焦一条来源明确的本机会话，在右下详情选择次级动作“交接任务”；批量选择不会自动生成工作包。
- 系统先说明当前来源能携带“原生会话”还是“只读会话内容”。Codex 支持根会话和内部记录原生导入；其他已有 Markdown 导出能力的客户端先使用只读内容。
- 用户填写目标、已经完成、接下来、阻塞/风险和验收标准；这些内容不会由系统读取会话后自动生成。
- 可选 Git 检查点记录 remote、branch、HEAD、工作树状态和已跟踪文件差异。未跟踪文件正文、素材和临时输出只有经系统选择器明确加入附件时才进入包。
- AgentDesk 先生成同一种不可变加密快照。跨 Mesh 或交给另一个人时保存为便携 `.agentdesk-task`，只显示一次高熵解锁码，文件与解锁码分开发送；同一 Mesh 内也可以选择满足协议、权限和连接条件的确切目标设备直接发送。外层密文不明文暴露标题、Agent、项目或附件名。
- 便携接收方从“活动”选择“导入任务包”并输入解锁码；同 Mesh 接收方在 `task.package.receive` 已开启的前提下仍须逐次接受。两条通道随后都验证密文完整性、清单、大小、逐项哈希和适配器，再选择本机 Agent/Profile 与任务资料保存目录。
- 原生导入遇到同一会话 ID 的不同内容会停止，绝不覆盖。成功后标题标出来自哪位交接人/来源 Agent；只读模式则保存会话 Markdown、任务说明、Git patch 和附件。
- 来源会话、项目和文件始终保留。接收端可继续工作后，发送人自行决定是否归档来源；系统不自动删除、双向同步或合并两边后续变化。
- 同一流程可以交给自己的另一 Agent，也可以把整个任务包交给另一个人。两人不必加入同一个 Personal Mesh；跨 Mesh 时继续由他们自行选择文件交换通道，不能把普通文件交换描述成已经自动连接。
- 同一 Mesh 直送已贯通 `task.package.transfer.v1`、独立 `task.package.receive`、逐次接受、目标设备公钥独占 envelope、完整密文哈希和共同导入路径；旧端或失败路径可以保存**同一个密文快照**为便携文件。传输层认证的是来源 `deviceId` 与设备名称；来源 Agent 名和交接人是受包完整性保护的发送方声明，不能写成由全局 Agent 目录认证。

## 11. 显式发送相关文件

- 发送端用系统文件选择器选定文件，界面不能提交任意路径。
- 接收端看到来源设备、文件数量和大小后，明确选择保存目录。
- 文件使用加密分块、逐块确认、全文件 SHA-256、背压和偏移续传；路径穿越、符号链接、目录和静默覆盖均被拒绝。
- 取消或失败只清理 AgentDesk 管理的暂存/partial，不会删除已经完成的用户文件。

## 12. 查看或控制自己的另一台电脑

- 从设备详情在右下统一详情面板打开隔离远控工作区；Header、顶部 Agent、左下会话和 Footer 保持原位，返回后恢复此前右下详情与会话状态。
- 目标端出现独立同意窗口，`screen.view` 持久权限和本次同意缺一不可；控制键鼠还需要 `input.control` 和第二次本次同意。
- 被控端始终显示控制设备和停止按钮；`CommandOrControl+Shift+Escape` 可紧急停止。
- 控制台可同时放入最多四台设备，但只允许一个当前输入目标；切换前释放上一设备的全部按键。
- 当前目标使用用户选择的画质，后台目标自动降为 360p/2fps 缩略图；诊断显示 LAN、P2P 直连或 TURN 中继，不显示候选地址或凭据。
- “返回工作台”先释放全部远端输入并降为仅查看，画面连接可留在后台且顶栏显示活动提示；“断开”才结束对应媒体会话。

## 13. 当前验证边界

当前 `0.10.1-preview.1` 的证据分层如下：完整 Node 套件共 517 项，516 通过、1 项仅 Windows 跳过、0 失败；TaskPackage 安全定向 25/25，发布安全定向 14/14。临时 userData 下真实 1040 × 840 Electron UI 为 21/21，覆盖全新首 Agent、重启恢复、设备向导 Shell 与状态投影、TaskPackage 直送资格和状态投影，以及既有固定几何、弹窗、会话、传输和远控任务路径。

成品证据单独记账：当前 macOS unpacked `AgentDesk.app` 已通过独立 fuse/ASAR verifier，118/118 个常规文件的整文件/分块 SHA-256、五项 fuse 和 `ElectronAsarIntegrity` header hash 均符合实际字节，且不存在 `default_app.asar`。这个 ad-hoc unpacked 结果不证明三次首次使用 smoke、Developer ID、公证、Gatekeeper 或可分发 DMG 已通过。

发布事务代码已把稳定开关固定为 `stableAllowed=false`，并要求精确 DMG、portable、`SHA256SUMS.txt` 三项资产依次经过 Draft、macOS/Windows 原生 runner 重下载、发布后无 token 匿名重下载与失败回 Draft；公开过再失败的 candidate 不得复用 Tag/version。14/14 只证明这些策略的纯代码边界。目前尚未配置真实签名凭据、受保护 `preview-release` 环境或真实 Preview Tag，因此没有公开 `v0.10.1-preview.1`。

两个隔离 endpoint 的真实 Electron WebRTC 分别在局域网直连和本机 signaling 路径完成设备认证、签名目录/库存、显式刷新、SessionPointer、184,333 字节文件和合成远控画面。这个 E2E runner **尚未发送 TaskPackage**：它证明既有认证传输底座仍贯通，不是 TaskPackage 直送数据面的 Electron E2E 证据。

物理双 Mac 的证据单独记账：同一局域网 host/UDP 认证 DataChannel 完成 562,009 字节库存、9 个 Slot、638 条 SessionReplica 落库，revision 7 → 8 → 9，连续 5 分钟无错误或断开。它关闭的是双 Mac 大库存、显式刷新和当前 4 分钟全快照恢复基线，不覆盖下面这些公开稳定版门禁：

- 两台物理电脑跨真实家庭 NAT、对称 NAT、CGNAT、IPv6 和 UDP 禁用环境；
- 真实 coturn 的 UDP/TCP/TLS 强制中继；
- macOS → macOS、macOS ↔ Windows、Windows → Windows 的屏幕、键鼠、DPI、多显示器和 IME；
- Windows portable 包内 helper 的真机编译、权限和 UAC 降级行为。
- 断网重连、睡眠/唤醒、长期可达与撤销后的物理防重连。

因此“代码纵向链路与本机自动化已实现”“unpacked verifier 已通过”和“局域网库存有物理证据”都不表示他人已经可以下载安装。GitHub-hosted runner 未来完成匿名重下载，也只证明 URL、字节、摘要、签名与自动化首次使用，不替代浏览器 quarantine、Windows MOTW/SmartScreen/Defender/UAC 和物理干净机首启。物理双机 TaskPackage 接受/拒绝/撤权/断线恢复、真实公网 NAT/TURN、长期连接恢复和 Windows 文件句柄/清理矩阵仍开放。当前候选是 `0.10.1-preview.1`，历史 `0.10.0` 不补发为稳定版；无人值守、登录界面、UAC 安全桌面、通用远程 Shell 和任意命令仍明确不做。
