# Catshelf（猫架）产品定义

AI 也是项目的使用者：通过 [本地只读 CLI 与定制指南](AI_INTERFACE.md) 发现能力、核对环境、查询会话和预检外部环境接入；不要求专属工具/MCP。公司 API 的 provider、模型和密钥继续归官方客户端或外部配置工具所有，不为 AI 开放任意执行、存储写入或绕过确认的入口。

当前源码验证、历史物理证据及未关闭门禁统一见[验证记录](VALIDATION.md)；本页不另行维护测试数字。

## 一句话

Catshelf 是一个本地优先的个人 Agent 控制台：它整理 AI 编码客户端的账号槽位、逻辑会话、额度和工具，并可把同一个人的这些 Agent 与会话扩展到多台可信设备。

当前 `0.10.1-preview.1` 开发版已经贯通有人值守 Personal Mesh 的代码链路：版本化首次使用、双方身份确认的设备任务向导、长期存在的全局 Agent 员工库、Blueprint/Deployment/可恢复首次准备、跨设备会话库存、会话信息发送、选定文件传输、便携与同 Mesh TaskPackage、远程查看、键鼠控制、多设备控制台，以及局域网优先、签名信令回退、STUN/TURN 配置和连接诊断。TaskPackage 从一条本机会话固定人工阶段检查点、原生会话或只读内容、Git 基线与已跟踪差异和明确附件，生成可跨 Agent、设备或人与人传递的同一种加密快照；它可以保存为便携文件，也可以在目标设备已认证、协议与权限满足时直接发送。接收方先接受并验证，再选择目标 Agent 与运行位置，来源副本保留。Codex 已支持根会话与内部记录原生导入，其他已有 Markdown 导出能力的客户端先保存只读内容。Agent、AccountBinding、AgentSlot 的新增、归属、合并、拆分和三种删除范围已经进入真实语义 IPC；已就绪远端可固定语义打开，未就绪远端只可在 `agent.prepare` 授权与目标端有人确认后准备。Device Lens、Agent、Slot、会话焦点/勾选、副本来源、全局弹窗、远控会话和传输草稿使用独立 UI 上下文。主窗口以 Header、顶部 Agent、下方会话列表和 Footer 为主。会话列表横跨下半区，隔离远控打开时使用 316px 右侧区域。工作台以卡片名册呈现 Agent。窗口顶栏只有文字标题、设备视角、收件箱和系统：设备管理在设备视角下拉的最后一项，工具与设置在“系统”这一页的两栏里，新增 Agent 与导入 Codex 在 Agent 标题行的“招募”里。名册最前面是“全部”，选一只猫只看它的会话，选“全部”看全部；卡片上的打开、档案、额度和运行位置都只作用于那只猫，不改变正在看的列表。名册卡宽 180px，少量时左对齐。每张卡用姿势和状态灯表达活动，用徽章和按钮表达需要用户做的事，并显示五格可信额度和运行位置，提供打开与档案。单账号额度从卡片打开，跨账号额度从 Agent 标题行打开，两者使用贴近入口的浮层。设备、工具、收件箱、设置各自打开独立弹窗，会话列表顶栏右侧承载复制、打开目录、导出和送出，支持焦点单选和显式批量选择。送出包含发送到设备与交接任务，收件箱承载待处理事项、送来的任务包与传输记录，Footer 以一行对白显示全局状态。画面是一张“台灯下的书桌”：顶栏和页脚是桌子的前后沿，猫坐在小搁板上、名牌挂在下面，会话是一本摊开的账，主按钮是一枚朱印，弹窗是贴着标签的档案夹，夜间是一圈台灯的光。看的字（标题、按钮、标签、名字、数字、表格）是点阵字，读的字（成句的说明、提示和填进去的内容）是系统正文字体；颜色各管一件事（木做结构、纸做内容的底、朱红只给主动作和选中、蜂蜜黄只表示正指着哪里、绿黄红只在小灯珠上）。动效逐帧、可打断，系统开启减少动态效果时停用，不计分；启动是“开灯”、关闭是“关灯”，见“开灯与关灯”一节；声音是一套照老掌机声音芯片现场合成的短音效，见“声音”一节。自动化与真实窗口证据以验证记录为准。物理双 Mac 已完成局域网认证通道和大库存/刷新这一项窄验证；TaskPackage 物理直送、长期可达与断网恢复、真实公网 NAT、coturn 强制中继及 macOS/Windows 四向权限矩阵仍是公开发布前验收，不能把局部证据写成整个物理矩阵完成。

文档分工保持清楚：本文记录当前产品事实，`FUNCTION_AUDIT.md` 记录功能状态和剩余缺口，`AGENTDESK_MULTI_ACCOUNT_MANAGEMENT_ARTICLE_V4.md` 是面向使用者的多 Agent / 多账号 / 多设备说明，`PERSONAL_AGENT_MESH_PLAN.md` 是获批后的实施权威与阶段门禁。说明文章中的目标态不能替代当前状态和真机验收结论。

## 核心对象

| 对象 | 含义 | 示例 |
|---|---|---|
| 客户端类型 | 数据格式和启动方式 | Claude、Codex、Cursor、Kimi |
| 账号槽位 | 一份独立本地数据目录 | 工作 Codex、个人 Claude |
| 身份组 | 同一登录在不同客户端形态中的归组 | Codex Desktop + Codex CLI |
| 历史会话 | 本地已有的会话记录 | 某项目的一条 Codex thread |
| 工具记录 | 已知桌面 App / CLI 的安装与版本状态 | Homebrew 安装的 Codex CLI |
| TaskPackage | 用户显式固定的一次工作交接快照 | 会话 + 阶段说明 + Git 检查点 + 明确附件 |

这些对象不能混为一谈。历史会话是可浏览记录，不是待执行任务；工具记录是安装状态，不是聊天连接。

Personal Agent Mesh 稳定区分全局 AgentIdentity、实际登录 AccountBinding、设备 Device、运行位置 AgentSlot、逻辑会话 ConversationIdentity、SessionReplica 和物理会话记录。Agent 是全局管理主轴，设备是筛选轴，具体动作最终落到明确的 `deviceId + profileId` 和会话副本；同一账号出现在多台设备不会因此重复生成 Agent。

## 用户主流程

1. 选择长期存在的 Agent 员工和当前工作环境；没有运行位置时点击“首次准备并打开”，已有 Deployment 时直接打开。
2. Catshelf 只在受管 staging 中创建白名单配置；安装、登录、验证码和系统权限仍在目标设备与官方 App 内完成，验证成功后才原子提交 Profile/Slot/Deployment。
3. 应用启动、密钥解锁恢复和定时轮询只观察准备状态；没有登录信息时保持“需要登录”，已有该 Profile 的身份信息时可收敛为 ready，但都不会自动打开下载页、登录页或官方客户端。只有用户明确点击继续或打开才产生外部界面。
4. 在名册里选一只猫看它的会话，或选最前面的“全部”看全部 Agent 的会话；范围按设备视角分别记忆，底层仍是“当前 Agent / 全部 Agent”两种范围。
5. 搜索、排序并查看一个会话的元数据。
6. 单击一行只聚焦详情；显式勾选后形成批量动作集合。两者都使用统一的“路径 + 坐标”，并在多副本时先明确来源，再复制、发送、定位或导出。
7. 一整项工作需要换 Agent、换设备或交给另一个人时，从聚焦会话选择“交接任务”，人工补齐阶段检查点并生成加密 TaskPackage；接收方从“活动”验证、选择目标运行位置并导入。
8. 四个对象各有一页：猫的档案从卡片上的“档案”进入，分资料、位置、账号、调用、送走五段；设备从设备视角下拉进入；收件箱和系统在顶栏，系统页左边是工具、右边是设置。点卡片额度或名册的「额度总览」，在浮层中查看额度。
9. 从工具弹窗检查、打开或显式维护本机应用与 CLI。
10. 按需从设备视角下拉的“管理设备”建立个人设备网，用一次性配对码加入另一台自己的电脑，并按“全部设备/某台设备”查看去重后的 Agent 和会话；进入明确远端设备时先看已落库快照，再只对该目标按需刷新。
11. 在会话列表顶栏复制会话信息、打开目录或导出所选会话。需要发送会话信息或交接任务时用同一排的「送出」；别人送来的任务包和传输记录在「收件箱」，自上而下是要你处理、送来的、记录三段。
12. 在目标端逐次同意后，在右下统一详情面板的隔离远控工作区查看或控制一台到四台设备；其他两个面板和 Header/Footer 保持原位，且始终只有一个当前输入目标。

## 能力范围

### 账号与身份

- profile/session 路径可自动推断或手动设置；
- 受支持的桌面 App 使用所选 profile 启动；
- 客户端显示名、官方包名和可执行文件名分别由注册表声明；Codex 在 macOS 上识别当前 `ChatGPT.app`，不会因产品标签仍叫 Codex 而误判未安装。Claude、Codex、Kimi Code 与 Cursor 的每个受管 Profile 都使用独立 `user-data-dir` 和客户端专用会话环境，同一官方程序可并行承载多个 Profile；已知不接受独立目录的 Kimi Work 只允许官方默认槽位，不伪造隔离多开；
- 启动前精确检查同一 `user-data-dir`，不重复拉起；Catshelf 正常退出默认关闭自己启动的 Profile，显式选择保留时说明退出期间不再监管；
- 每个受管 Profile 的 `Crashpad/pending` 受 100 文件/200 MiB 双上限和一分钟 5 个同尺寸 dump 的风暴熔断保护；普通关闭只处理 Catshelf owned 进程，已确认磁盘事故可按精确 Profile 路径停止 Catshelf 自己 Profiles 根内的升级/异常退出遗留进程，无所有权的官方默认/custom 目录不被后台清理或停机；安全清理只删除直属 dump/sidecar，不触碰 Agent 数据；
- 添加账号是 Agent 标题行的一个“招募”弹窗，分四段：新来一只、把已有的领回来、拖进来、交给 AI；首次使用的“导入 Codex”和“高级：手动导入运行位置”打开它的对应段。客户端在原有七种之外加了 OpenCode、Gemini CLI、Qwen Code（会话扫描、终端启动与账号隔离）。已登记客户端都能在默认位置、环境变量目录、主目录（最多四层、跳过隐私授权目录和云盘、有时间与数量上限、可取消）和用户指定的文件夹里被认出，多选后一次登记，只登记目录、不复制登录，已登记的标为已在台面上；Codex、Claude CLI、Kimi Code、DSH 可以粘贴密钥或令牌、或填接口账号（地址、密钥、模型），密钥只交给该账号自己的官方客户端，Catshelf 不保存；DSH、Kimi Code、Codex 与 Windows/Linux 的 Claude CLI 登录文件可以导入到新的独立目录，复制前提示原处可能掉线；成品命令行提供同源的 `profiles discover`、`create`、`set-key`（只读标准输入）、`status` 与 `import-auth`；
- 同一登录可通过手动 identityKey 或本地指纹归组；
- Windows 支持传统安装与 Store/MSIX 路径；
- 配置使用本地 JSON、原子写入和备份。

### 会话历史

- 支持 Claude Desktop、Claude CLI、Codex、Cursor、Kimi Code、Kimi Work、DSH、OpenCode、Gemini CLI、Qwen Code；DSH 只列会话，不导出正文；
- 支持与 Device Lens 正交的当前 Agent/全部 Agent 范围（由名册上选一只猫或选“全部”决定）、精简/详细列、搜索和排序；
- 支持只服务定位动作的临时多选；复制与 SessionPointer 发送使用同一确切副本集合，不产生持续任务状态或自动交接编排；
- Codex 按用户根 thread 形成逻辑会话；上下文压缩不增加列表行，guardian/subagent 等内部 rollout 默认隐藏；
- 右侧详情是单会话视角；
- 来源允许时可定位文件或导出 Markdown；
- 扫描与浏览不修改会话源文件。
- 新回复：一条 Claude 命令行或 Codex 的对话回完了、人还没接着说、也没在 Catshelf 里点开过，行上标题加粗、前面一个小气泡、后面“新回复”小标，卡片上给出条数，窗口不在前台时响一声（半分钟内最多一声）。Catshelf 看不到人在官方客户端里读没读，所以叫“新回复”，不叫“未读”；其他客户端和别的设备上的会话不标。首次启用之前的回复不标。点开这一行或用“全部标为已看”就不再标。
- 在跑：最近 90 秒内有新内容、还没回完的会话，行上三个点逐格走并写“在跑”；停着等人点允许的对话没有新内容，不算。
- 颜色标签：五种（红·方块、黄·三角、绿·圆点、蓝·菱形、紫·星），每种一个颜色加一个形状，一条会话最多一个；人自己打（右键、行上的“标签”、选中后按 1–5、0 去掉、勾选几行后在顶栏“打标签…”）、自己起名（双击筛选条里的形状，最长 12 个字）。应用不替人打标签、不规定含义、不排优先级。
- 筛选与排序：搜索框左边的“新回复”开关和五个形状只决定这一次看哪些行，不记进设置，对正在看的和已勾选的会话的处理与搜索框相同；“显示”里有最近活跃（默认）、新回复在前、按标签三种排序，排序方式会记住。
- 标签和“看过”的记号只存在本机 Catshelf 的 `session-marks.json`，不写进任何官方客户端的文件，本期不随 Personal Mesh 同步。

### 任务交接

- 聚焦一条本机会话后可显式生成 `.agentdesk-task`；它是一次不可变检查点，不是持续任务队列或自动同步关系；
- 检查点中的目标、已完成、下一步、阻塞/风险和验收标准由人填写，系统不从会话自动猜测；
- Codex 包含可验证的根会话与所属内部记录；Claude CLI、Kimi Code、Kimi Work 等已有导出能力的来源先携带只读 Markdown；
- 可选项目现场记录 Git remote、branch、HEAD、工作树状态与已跟踪差异；未跟踪文件正文只有被明确选为附件时才进入包；
- 包使用流式 AES-256-GCM 与一次性高熵解锁码，外层不明文暴露标题、Agent、项目或文件名；解锁码只显示一次，不进入包或历史；
- 接收端先解密和逐项校验，再选择本机 Agent/Profile 与资料目录；同 ID 异内容拒绝覆盖，导入失败回滚；
- 来源会话和文件始终保留。跨人或跨 Mesh 通过用户选择的便携文件通道交换；同 Mesh 目标同时满足认证连接、`task.package.transfer.v1` 和 `task.package.receive` 时，可以发送同一标准密文快照。接收端逐次接受，完整密文哈希通过后才解封并进入共同导入；失败或旧端可保存同一快照为便携文件。
- 直送卡片中的来源设备 ID/名称来自认证传输事实；来源 Agent 名与交接人标签是包内声明，不等同于目录认证身份。

### 调度中枢（后台对话）

- 你对自己的 Agent 说一句话（“用我的 Codex 工作号检查一下这份改动”），那个 Agent 通过成品命令行让另一个账号在后台跑一段对话，再取回结果。Catshelf 只中转这一次调用并记账：它自己从不发起、不排队、不重试、不定时、不替人挑账号，也不把一段对话的结果交给另一个账号。
- 只有在猫的档案里打开“允许别的 Agent 调用它”的账号才能被叫，默认关；“允许它改文件”另开，默认只读。工作目录必须在系统页里允许过的文件夹里；同一只猫一次只跑一段，同时运行有上限（到了就拒绝，不排队），层层转叫最多两层，额度见底的账号不接。开关、文件夹和上限只能在桌面上改。两个开关在猫的档案的“调用”一段（跟着展开的那个本机位置走），文件夹和上限在系统页“设置”栏的“后台对话”一块；客户端不能被调用时档案里写明原因。复制会话信息、发送到设备、交接任务、账本里的“后台对话”和“允许被调用”各有一张说明纸条，写清谁做、对话动不动、离不离开这台电脑。
- 能被叫的：Codex（同一账号目录里的 Codex 命令行）、Claude CLI、Gemini CLI、Qwen Code。桌面版客户端只能开窗口；Kimi Code、OpenCode、DSH 的无界面方式按官方文档做不到“提示词只走标准输入”或“只读”，暂不支持。
- 账本里一段后台对话只占一行：标题是调用方给的，副行写“后台对话 · 谁叫的谁”，前面一盏灯（启动中空、运行中朱红一闪一闪、已完成绿、失败暗红带叉、已停止灰），旁边是用时和“停止”。不显示内容；被叫账号自己的会话找到以后，这一行就是那条会话，可以点开阅读、复制会话信息。
- 桌上：信封从发起的那只猫沿搁板飞到被叫的那只，它醒来开工；在跑时两只之间的木板上有一条慢慢流动的点线；结束时结果飞回去，被叫的那只跳一下；失败是墨色封印的信封飞回、它摇头；你叫停时点线断开、它收起电脑。发起方只有在 Catshelf 确实知道是哪只猫时（它中转的上一段对话，或发起的进程就在那个账号的目录里）才从那只猫飞出，否则从桌子边缘进来，自报的名字只当标签显示。
- Catshelf 只存界面显示的东西（标题、调用方标签、目标、状态、时间）和会话记录在哪；提示词和回答不写进它的任何存储。退出 Catshelf 时在跑的后台对话一并停下。

### 三个动作：复制、交接、调用

界面、命令行和文档统一用这三个词：

| 动作 | 是什么 | 谁做 | 对话去哪了 | 入口 |
|---|---|---|---|---|
| 复制 | 把一段对话的位置（路径和坐标）复制出来，贴给另一个 Agent，它自己去读 | 人 | 没动 | “复制会话信息”（会话区唯一的填色主按钮，格式不变） |
| 交接 | 把整件事搬到另一台电脑或另一个人那里接着干 | 人 | 搬走一份，原来那份不动 | “送出”里的“发送到设备”（只送位置）和“交接任务”（对话、代码改动、备注打成一个包） |
| 调用 | 你的 Agent 让另一个账号在后台跑一段对话，把结果拿回来 | 人对自己的 Agent 说一句话，那个 Agent 通过 Catshelf 中转 | 没动，还在你正在聊的那个 Agent 那里 | 账本里的后台对话；档案里的“允许别的 Agent 调用它” |

同一台电脑上换一只猫接着干，用的是复制：人复制、人贴过去。Catshelf 没有“把对话直接塞给另一只猫”的动作；只有调用时，内容才由 Agent 通过 Catshelf 自动送过去。复制只演盖印和一张小条飞进页脚，不演“对方收到”，因为贴到哪里发生在应用外面。

### 额度与活动

- Codex 通过本机官方 app-server 获取额度；
- 结果按账号缓存，失败可降级到 stale/error；
- 无可靠来源的客户端显示 unsupported；
- 活动和额度是两条独立信号，卡片分别显示真实活动和可信额度。
- 一只猫同时在跑几条对话（本机各运行位置最近 90 秒有新内容、还没回完的会话，与调度中枢正在跑的取大），名牌状态那一行写“N 条在跑”；远端位置没有这项数据，不计也不显示 0 条。
- 路径、额度等持久待处理事项只进入 Header 的“活动”弹窗。

### 工具维护

顶栏“系统”这一页的工具一栏提供固定目录中的桌面 App、CLI 和系统终端，一行一个：

- 发现安装状态、本地版本与安装来源；
- 查询受信任的 npm、Homebrew 或 GitHub 最新版本；
- 打开桌面 App、系统终端或已发现的 CLI；
- 对识别到且可写的 npm/Homebrew/uv/自身更新器安装执行显式更新；
- 无法安全自动维护时只打开官方页面。

CLI discovery 是只读能力：只解析启动器，不附加工作参数，不建立连接或会话。

客户端有序更新（只在 macOS 上）：同一个客户端开着几个账号时，应用的更新器要等它们都退出才能换上新版本，做不到互不影响，Catshelf 让它有序（[ORDERLY_UPDATE_PLAN.md](ORDERLY_UPDATE_PLAN.md)）。

- 有更新在等时，这些账号的卡片上有一个小记号，“工具”里这个应用的那一行给出详情和“一起重开…”：确认后逐个关掉 Catshelf 打开的这些账号，等新版本换好，再各带各的数据目录打开。确切（磁盘上的版本更新了）与推断（更新器已下载新版本，目前只有 Claude 能看出来）如实标注，判断不了就不显示。有后台对话时要人明确勾选才继续；等不到新版本就停住并说明。
- 人自己在客户端里点了更新以后，收件箱和“工具”里提供“原样重开”刚才开着的那几个。
- 更新命令行工具前，它的账号有对话在跑就先问一句。
- Catshelf 不下载、不安装更新，不改客户端的更新设置，不替人决定什么时候重启；更新器自己重新打开的默认实例不去碰。

### 猫

每个 Agent 是一只坐在搁板上的像素猫。猫是所有者在图鉴上批准的那一套：20×18 格（卡片上一格 4 像素，80×72），所有姿势共用同一个头，所以不管它坐着、揣手、睡着还是摊成饼，都认得出是同一只；花斑和条纹画在身上，动的时候跟着身体走；动作一帧一帧画出来，没有拉伸和旋转。头顶另留两格透明的空，跳到最高时帽子不会被切掉。所有画猫的地方共用一个钟：每只看得见的猫按它当前动作的帧率走，窗口藏起来时停；系统开启“减少动态效果”时只画当前状态的第一帧。

它一直在演的状态，每一个对应应用里一个真实的判断：

| 动作 | 什么时候 |
|---|---|
| 在岗 | 客户端开着，会话最近没在生成 |
| 干活 | 有会话正在生成（会话记录 90 秒内还在动）；同时只有 1 条在跑 |
| 忙 | 同时 2–3 条在跑：干活加快，旁边一摞纸（一条一张），隔几秒额头冒一滴汗 |
| 抓狂 | 同时 4 条以上在跑：两只爪子轮流砸键盘，眼睛瞪圆，整幅画在 2px 格子上抖，键帽和纸屑往外飞，头顶先两个叹号后一团汽，纸摞高而歪 |
| 赶来 | 刚点了打开，客户端还没起来 |
| 玩耍 | 一天内用过，现在没开 |
| 揣手 | 一到三天没动静 |
| 打盹 | 三到七天没动静 |
| 冬眠 | 七天以上没动静 |
| 迷糊 | 找不到它的目录（路径失效） |
| 累了 | 卡片的能量格变黄（可信额度剩 10%～30%） |
| 摊成饼 | 卡片的能量格变红（可信额度不足 10%，或已触发限额） |

卡片上已经有两样东西：状态行说它在干嘛，能量格说它还剩多少力气。一只猫一次只能演一件事，先后是：迷糊、干活（以及更忙的忙、抓狂）、赶来这几种眼下正在发生或要你处理的事先演，状态行和猫说的是同一件；其次是能量格变红（摊成饼）或变黄（累了）；最后才是在岗、玩耍、揣手、打盹、冬眠这些平静的作息，活动未知时坐着待命。额度未知、过期或来源对不上时不影响猫。

播一遍就回到当时状态的动作：

| 动作 | 什么时候 |
|---|---|
| 跳一下 | 点卡片选中它 |
| 被摸 | 点猫本身 |
| 炸毛 | 摸过之后马上再点它一下 |
| 好了 | 点打开后客户端起来了；导出完成时页脚那只猫也这样 |
| 摇头 | 打开出错；导出出错时页脚那只猫也这样 |
| 跳上来 | 开灯时、新来的一只、换了工作环境 |
| 跳下去 | 被送走 |
| 睡下 | 关灯时；或它自己从醒着变成睡着（打盹、冬眠） |
| 醒来 | 开灯时；或它从睡着又开始用 |

点了打开、客户端还没起来时先演“赶来”；需要你登录或安装时只飘一句话，不摇头。页脚那只猫揣着手，复制会话信息时跳一下。“全部”那张卡是三只猫的合影，不动。

外观只有三项：毛色、项圈颜色、一件配饰，在“编辑 Agent”里选，左边是会动的预览。毛色 24 种，分三组：家猫 12 种（橘猫、奶油、狸花、银虎斑、玄猫、白猫、礼服、奶牛、三花、玳瑁、暹罗、蓝灰），有来历的 7 种（招财、青花、水墨、锦鲤、虎头、熊猫、掌机绿），跟着客户端 5 种（Codex、Cursor、Qwen、Copilot、OpenCode）。配饰 12 种：不戴、围巾、蝴蝶结、领带、铃铛、眼镜、墨镜、草帽、贝雷帽、斗笠、耳机、小花。新招募的猫默认穿它那个客户端的毛色（有的话，连同那种毛色自带的项圈）；已有的猫外观不变。

“跟着客户端”这一组只取颜色，不画任何标志、字标或图标；名字只用来说明这只猫属于哪个客户端，不表示与任何厂商有关联或得到认可。色值在 2026-11-24 对过各家的官方资料：

| 毛色 | 用到的颜色 | 来源 |
|---|---|---|
| Codex | 毛 #f9f9f9、描边 #0d0d0d、项圈 #181818（黑和白） | openai.com 自己的样式（primary-100、surface-secondary、primary-solid）；openai.com/brand 不公布配色。原先猜的 #10a37f 只在 chatgpt.com 的个别按钮里出现，不是现行官方色，已拿掉 |
| Cursor | 毛 #26251e、浅色 #f7f7f4、描边 #14120b、项圈 #f54e00 | cursor.com/brand 链接的官方标志 SVG 与 cursor.com 样式（主题前景、背景与强调色） |
| Qwen | 毛 #082dff、浅色 #f7f8fc、描边 #232326、条纹 #0008c9 | qwen.ai 样式的品牌主色，与 QwenLM/qwen-code 仓库里的标志 SVG 相同；原先猜的紫色 #615ced 不是现行品牌色 |
| Copilot | 毛 #232925、浅色 #f2f5f3、描边 #101411、花斑 #08872b、项圈 #0fbf3e | brand.github.com/foundations/color（GitHub 灰与绿）；Copilot 没有单独的配色，官方说它不该和 GitHub 主品牌分开 |
| OpenCode | 毛 #626262、浅色 #d2d2d2、描边与项圈 #1f1f1f | opencode.ai/brand 的三档墨色；原先猜的终端绿不在官方资料里 |

图鉴里另有四种按客户端取色的毛色，核对时发现它们的品牌规定不允许这样用，已经拿掉，对应客户端的新猫仍用原来的确定性默认：Gemini（Google 的品牌规定明确不许在作品里使用 Google 的品牌颜色，包括网站和应用）、Claude（Anthropic 把品牌元素算作商标，只能在其事先批准的材料里使用）、DeepSeek（使用条款不许未经许可使用商标或其他显著品牌特征）、Kimi（品牌手册把颜色列为品牌资产，使用须先申请许可）。

外观是 Agent 身份的一部分，随签名目录事件在自己的设备之间同步；事件的字段和形状没有变。为了让旧版本也读得懂，存下来的 `breed` 永远是旧版认得的八种之一、`accessory` 永远是旧的五种之一，新毛色另记在 `coat`、新配饰另记在 `wear`。旧版本的设备看到的是最接近的那只旧猫（比如青花显示成白猫、斗笠显示成草帽），它改名之类的编辑不会冲掉新毛色；它若真的换了毛色或配饰，新版本就听它的。猫动起来是否顺眼、颜色在夜间是否分得清，要在真实窗口里看，见 [VALIDATION.md](VALIDATION.md)。

### 开灯与关灯

启动是“开灯”，关闭是“关灯”，和“台灯下的书桌”是同一个场景。

- 开灯：窗口出现时桌子是暗的（窗口自己的底色也是这种夜色，不会先闪一下亮的），只有木头的前后沿；灯分三档亮起来，搁板从左向右伸出去，名牌顺着绳子一张晚一点落下来、回弹一下，每只猫在自己的数据到了以后从搁板后面跳上来、落地压一下身子，账本摊开、会话一行行从左边写进来（最多演十二行），最后页脚的猫说第一句话。数据快的时候全程约一秒半。每扇窗只演一次，后台刷新不会再演；macOS 上关窗后重新打开只短短地开一下灯。
- 数据还没到：不转圈，不放进度条。搁板和空白名牌先摆好，猫的位置是一个网点画的影子，账本摊开着只有点线的空行；等过两秒，页脚如实说在等什么（正在读取设置、设备和 Agent 目录、账号或会话）。每只猫各自到了就各自跳上来。
- 打开之后：新来的猫让出位置、搁板长一截、名牌落下、猫跳上来；送走的猫跳下去、名牌被提上去、后面的卡片挪过来补位，整个过程搁板不断。你自己的操作带出来的新会话行从左写进来，后台刷新出来的行直接出现。弹窗是从桌上抽出的档案夹，从下往上三档，合上更快。
- 关灯：猫一只接一只趴下睡，账本合上，灯分三档暗下去，窗口关闭，不到半秒。退出前要先关掉 Catshelf 启动的客户端时，灯留一档，页脚写着在关哪几个，每关掉一个，对应的猫先睡下；有客户端关不掉时灯重新亮起来，页脚显示原有的提示，应用不退出。退出从不等动画：窗口没有回应时最多等 0.7 秒照常退出。
- 搁板是一条：从“全部”到最后一只猫坐在同一条木板上。名册放不下时，还有猫没露出来的那一头跟着猫一起化进桌面，靠“全部”那头的木板一直是实的。
- 动的规矩：位置落在 2 像素的格子上，走先快后慢的路，步子一帧比一帧小；落下的回弹一次，跳起来的落地压扁一帧；明暗用台阶，不用渐变；一组东西错开出现，整组不超过半秒；点一下或按一下键直接跳到最后的样子；系统开启“减少动态效果”时全部直接出现。动起来是否顺眼要在真实窗口里看，自动化只能证明帧值、时序和接线，见 [VALIDATION.md](VALIDATION.md)。

### 声音

声音照老掌机的声音芯片做：两个方波、一个 4 位波形、一个噪声声道，每秒写 60 行寄存器，音量 16 档。22 个音效全部在应用里现场合成，不带音频文件，不联网，每个都短于半秒，同属一个调。

- 只在“你做了一件事并且它有了结果”和“有事需要你”时响：选猫、点猫（每只猫的叫声由它的编号决定，叫过之后马上再点它一下会“电一下”）、打开账号及其结果（就绪、等你处理、出错）、额度第一次掉到最低一档、送走一只猫、勾选与取消会话、拖动排序时拿起和放下卡片、复制会话信息（盖印，每次最多三下）、送出、弹窗开合、展开菜单和小开关、换主题（开灯、关灯）、页脚那句话逐字出来、别的设备送来东西、应用启动（等第一次点按）。
- 悬停、滚动、打字、点一下会话行看详情、后台刷新都不响。窗口不在前台时只响“来了东西”和“等你处理”。同一时刻只有一个声音，新的打断旧的；开合、小开关和逐字不打断正在响的结果声。
- 三档：全部、只要要紧的（默认）、静音；开机声和逐字只在“全部”这一档。档位和音量在“系统”页的设置一栏，页脚最右端有一键静音；设置随其他偏好一起保存。
- 还没有的：“有设备开始查看或控制这台电脑”的提示音（主窗口目前收不到这个通知）。这些声音是否好听要在真实应用里听，自动化只能证明数值与接线，见 [VALIDATION.md](VALIDATION.md)。

### Personal Mesh（有人值守开发版）

- 全新用户可在“创建第一个 Agent”时一并建立仅限本机的 Agent 目录与设备身份；设备中心保留同一事务的高级入口。两条入口都不自动开放网络、发布在线租约或连接其他设备；
- 全新用户从“创建第一个 Agent”开始，本机目录与设备身份在同一受控事务中建立，网络登记保持关闭；已有 Profile 先进入无损迁移预览。缺失 `profiles.json` 是真实空状态并原子保存为 `[]`，不生成默认 Claude/Codex/Kimi Profile；未展示完成页前不提前记录向导完成版本，应用重启后可继续审阅。
- “添加设备”按身份确认、成员信任、认证连接、目录落库、库存落库和可以使用分步呈现。加入端先检查邀请并确认来源指纹，邀请端先确认申请设备身份，任一侧未确认时都不签发成员证书；“接收连接 30 分钟”只保留为高级恢复。
- 本机生成 Mesh Root 和设备 Ed25519 密钥，私钥经 macOS Keychain / Windows DPAPI 对应的 Electron 系统密钥保护加密；
- 设备、AgentIdentity、AccountBinding、AgentBlueprint、AgentDeployment、ProvisioningJob、AgentSlot、签名目录事件与 tombstone 写入独立 `mesh.db`，不污染 `profiles.json`；当前 schema v6 保留 v4 的 nullable suppressed Slot 语义，并在升级前生成包含已提交 WAL、经版本/完整性/外键校验的 `pre-v6` 回滚点；
- Agent 是长期员工：删除最后一个 Slot、Deployment 或 AccountBinding 都不会删除 Agent；每个工作环境始终投影完整员工库，没有 Slot 时显示首次准备，只有显式“删除 Agent”才产生目录 tombstone；
- 同一强账号标识的多个客户端形态归为一个 Agent，同机不同账号保持独立，跨平台只接受用户已有的显式身份关联；
- Profile 换号时 Slot 标记为 `identity-changed`，不把旧会话静默改归新账号；
- 新增入口明确区分“新 Agent / 新账号绑定 / 本机新运行位置”；合并 Agent、拆分 AccountBinding、移除运行位置、移除登录账号和删除 Agent 均展示对象范围，并由 Main 按 revision 重新校验；
- 删除运行位置、实际登录账号或整个 Agent 后，suppressed Slot 与 tombstone 会持久化到 SQLite；关闭并重开后仍保持删除结果，最后一个 Agent 也可删除到零，不按 Claude、Kimi 或其他平台补默认 Agent；
- 用户可让本机离开并重置 Mesh，重置只清除设备身份、密钥和 Mesh 缓存，不删除账号槽位、官方客户端数据或会话；任意远端设备和最后一个 Agent 都可删除；
- 一次性配对码使用设备签名、邀请 secret proof、X25519、HKDF 和 AES-256-GCM；设备权限、成员事件和撤销均由本地信任链验证；
- 全局 Agent/AccountBinding/Blueprint/tombstone 以无固定主机的签名目录事件为权威：握手交换来源连续向量，只补缺失事件，转发仍保留原始设备签名。双端并发修改不同字段自动合并，同字段稳定收敛并留审计；关系事务在 revision 过期或因果历史不完整时停止，删除永久压过旧库存、旧快照和并发旧编辑，同名重建使用新 ID；
- 握手把危险权限与线协议 feature 分离，只协商精确白名单 `catalog.events.v1` / `catalog.snapshot.v1` / `inventory.device-facts.v1`，并刷新当前 appVersion 等运行元数据。0.9.4 旧端继续走安全快照兼容，更旧端降级为 inventory-only，不接收未知目录消息；目录权限不对称显式跳过目录屏障，不会拖垮 `inventory.read`；
- 设备库存只允许来源设备写自己的 Slot 和会话副本；新连接在首份完整库存事务落库后才报告可用，已认证连接重新连接或显式“重扫”会通过固定 `remoteInventory:refresh` 请求新快照，并在连接存续期间每 4 分钟发布一次有界全量恢复快照；库存收发重读当前 `inventory.read` 权限，撤权立即终止现有连接，显式刷新按连接单飞、节流并限制等待队列；
- 现代 `inventory.device-facts.v1` 快照不携带全局 Agent、AccountBinding 或 tombstone；旧端兼容投影仅在接收端当前具备 `catalog.manage` 时增补本地未知对象，不能覆盖既有关系、提交删除或裁剪零 Slot/零 Binding 员工；
- 进入一个明确远端 Device Lens，或从设备中心查看该设备会话时，先渲染已落库缓存，再只对这一设备按需走固定刷新；应用启动、本机 Lens 和“全部设备”不 fan-out。无认证连接、临时 LAN 或已配置可达 signaling 路由时，刷新失败但保留离线快照，不冒充已同步；
- Mesh 密钥保护、会话聚合 IPC 或远端库存失败时，全部/本机 Lens 必须回退到当前 Agent 所属本机 Profile 的只读扫描，并明确标出本地模式；不得用空远端结果覆盖健康本地会话。此时远端会话、SessionPointer、文件和 TaskPackage 直送暂停，本地复制、定位、导出与便携 TaskPackage 仍可使用；
- 精确识别为 ad-hoc、无 Authority、无 TeamIdentifier 的已打包 macOS 开发版，普通启动会先用持久 Mesh 快照展示 Agent/Slot 与本地会话，不让重签名后的 Keychain ACL 阻断工作台。用户显式打开“设备”时才请求密钥访问和远端功能；正式 Developer ID 包、Windows 和开发态保持原有安全启动路径；
- 远端库存会话在落库前按接收端 canonical Slot 改写 Agent/AccountBinding：强会话使用 canonical Binding 重算 `conversationId`，弱会话继续使用来源设备作用域并保持 `conversationId`/`replicaId` 稳定；tombstone 或 suppressed/unassigned 已排除的 Slot 不会以旧会话残留。同一强账号键归并，同一强会话键折叠，弱标识不按名称、路径或时间猜测；
- “复制会话信息”仍只输出路径与坐标；“发送到设备”传输端到端加密 SessionPointer，离线时只在发送端本机密文队列等待；
- 文件必须由发送端系统选择器选取、接收端明确选择保存目录，采用分块、哈希、背压和断点续传；
- 控制端 Remote Surface 是右下统一详情面板内的独立沙箱 WebContentsView，目标端 Host Consent/Indicator 仍是本机专用沙箱提示窗；`screen.view`、`input.control` 除持久权限外还需要目标端本次同意；
- 多设备控制台最多四路，只有当前设备使用活动画质，后台设备降为低频缩略图，输入切换前释放上一设备全部按键；
- 已就绪远端只接受 `requestId + agentId + profileId` 的固定 `profile.launch`；首次准备只接受 Agent 与受限客户端枚举。目标端确认排队前、用户允许后且产生任何副作用前重新读取当前设备/权限并核对原连接代次，撤权、撤销、断连或连接替换后的迟到允许不能创建 ProvisioningJob；
- 局域网连接只在用户临时开放时监听；公网会合使用签名短租约，公开地址要求 HTTPS，TURN 长期 secret 只留在服务端，桌面只在内存持有短期凭据；
- 设备诊断只显示服务状态、候选类型、传输协议、LAN/直连/中继和权限，不显示 IP、SDP、完整密钥或 TURN 凭据。
- 主 Renderer 的 Device Lens、Agent、Slot、focused/checked 会话、SessionReplica、`utilityDialog`、设备详情、活动远控和两类传输草稿彼此独立；Device Lens / Agent / Slot 的显式选择写入稳定设置并在重启后恢复。旧设置没有这组记忆时，只在全部 linked 本地 Profile 唯一归属同一 Agent 时恢复该 Agent，不选列表第一项。打开或关闭全局弹窗以及 render、搜索、刷新都不会静默改写动作目标。
- 卡片视图移除独立的当前 Agent 栏，名册使用完整宽度。卡宽固定为 180px，卡片较少时左对齐，超出视口时由名册横向滚动，选中卡片自动露出。每张卡记住自己的运行位置，同一 Agent 内切换位置保留会话搜索和选择。卡片上状态只说一次：最近活跃时间和位置数收进提示文字，卡面只留状态、五格额度、运行位置和两个动作；“打开”落在卡片上显示的那个运行位置，不选中这只猫。最近活跃和额度摘要继续使用已有缓存。额度接受本机来源匹配、未过期、未到重置点且同一登录来源一致的成功快照，缺失时显示未知，冲突时显示来源不一致。

当前开发版不包含无人值守、远程 Shell、任意命令、服务端业务邮箱或自动任务调度。当前定向验证环境没有配置或验证长期可达的公网 signaling endpoint，隔离 Electron E2E 也尚未发送 TaskPackage；虽然双 Mac 局域网库存链路已有窄真机证据，公开稳定版前仍需完成 TaskPackage 物理双机直送与恢复、长连接/断网恢复、真实公网和跨平台网络/权限矩阵。

## 明确边界

下列能力不属于 Catshelf：

- 内嵌终端或统一聊天壳；
- 自己发起、排队、重试、定时或编排 Agent 对话（调度中枢只中转人通过自己的 Agent 明确发起的一次后台对话，并在它运行期间监管、记账）；
- 把多会话选择扩张为优先级安排、上下文拼接或自动交接编排；
- 任务队列、自动串行/并行工作流；
- 规划文档、任务材料或聊天上下文挖掘；
- 自定义可执行命令或协议接入；
- provider/API key 路由、token 托管（粘贴的密钥只交给那个账号自己的官方客户端，Catshelf 不保存）；
- 自动 transcript 同步、自动删除来源或把完整 transcript 上传云端；
- 团队、组织、多人设备共享和审批流；
- 通用远程 Shell、任意命令执行和凭据托管。

Personal Mesh 只能同步必要的目录与只读索引、显式发送会话信息或文件，并在单独授权后提供查看/控制；它不能成为绕过本机安全边界的第二条通道。

产品增加新功能时，若它需要持有一个“正在运行的会话”或把一个历史会话变成待执行任务，应视为越界，先重新讨论产品定位。调度中枢是所有者 2026-11-24 批准的例外：它只在调用方明确发起时持有那一个后台进程，结束或停止后只留标题和状态。

## 安全原则

- 密码、token、浏览器 Cookie 不进入 Catshelf 的存储、日志、Renderer 状态和命令行输出。用户粘贴的密钥只在内存里交给该账号自己的官方客户端：它的标准输入、它文档写明且只给这一个子进程的环境变量，或该账号目录里文档写明的配置文件；Claude CLI、DSH、Kimi Code 和 Codex 接口账号的写法会以明文留在该账号目录（权限只有本人可读），界面事先说明。
- Renderer 不持有 Node、文件系统或通用进程能力。
- 主进程对 ID 重新查表，不接受 renderer 提供的任意 executable、argv、环境变量或 URL。
- 会话来源只读；导出写入用户通过原生保存框选择的位置。
- TaskPackage 只在用户显式操作后读取一条可信本机会话；文件和附件路径来自 Main 的原生选择器。导入先验证加密、清单、整包与逐项哈希、适配器与冲突，再写入目标；解锁码不持久化。直送解锁材料只进入目标设备公钥独占并绑定 Mesh、来源/目标、transferId 与包哈希的 envelope，不使用 Mesh link key，也不进入 Renderer、历史或日志。
- 工具更新由用户明确触发，只使用固定目录生成的计划，不调用 sudo。
- Electron 成品必须从 `app.asar` 加载且不存在 `default_app.asar`；每个常规文件的整文件与分块 SHA-256 都必须匹配，archive header 必须绑定 macOS `Info.plist` 或 Windows PE 资源；`RunAsNode` 只服务现有两个固定 CLI launcher，`NODE_OPTIONS` 与 inspect fuse 关闭，embedded ASAR integrity 与 only-load-from-ASAR 开启。
- Catshelf 自更新必须校验 Release 元数据和 SHA-256；公开 Preview 只允许精确 DMG、portable 与 `SHA256SUMS.txt`，先 Draft 重下载、再公开匿名重下载，失败回到 Draft；正式 macOS 包必须签名、公证并通过 Gatekeeper，Windows 包必须绑定受保护的可信发布者身份。
- Mesh 私钥不进入 Renderer、日志或普通数据库；设备 IPC 只接受固定 ID 和有界名称，不暴露通用 channel、命令或路径。
- WebRTC 传输加密不能替代设备认证；offer/answer 只能通过双方共同登记且持有有效租约的信令服务交换，消息不能指定任意回复 URL。
- 远程输入只通过固定键鼠事件协议进入原生 helper；断线、失焦、切换目标、撤销和紧急停止都会释放按键。

## 产品完成标准

- 多个账号槽位可以稳定打开且不会被配置并发写坏。
- 所有支持来源的会话能统一浏览，单个坏文件不会阻断整个扫描。
- 同一 Codex 根会话无论发生多少次上下文压缩都只保留一行，内部子 rollout 不冒充用户会话。
- Windows 和 macOS 的真实路径、启动候选与失败原因可诊断。
- 工具中心能准确区分缺失、已安装、可更新和仅能打开官方页。
- UI、IPC、依赖和文档中不再存在会话执行或编排入口。
- 1040 × 840 窗口保持 58px Header、222px 顶部 Agent 和 38px Footer。会话列表常态占满下半区，额度浮层打开时维持全宽。隔离远控使用按需显示的 316px 侧区。Compact 无横向滚动。弹窗跟着内容长高，只在内容确实超过窗口时由内容区滚动；全新安装从空台面上的“招募第一只猫”开始，不再一启动就弹窗。按钮、数字和小标签使用随应用提供的点阵字体，长文字用系统字体。会话动作位于列表顶栏右侧，Footer 显示全局状态。真实 Electron 验收覆盖既有三语/双主题和工作台任务，并新增全新首 Agent、重启恢复、设备向导 Shell 与直送资格/接收阶段投影；后两项不冒充物理双机向导或 TaskPackage 数据面 E2E。
- 已配对设备能交换去重库存；明确远端 Lens/设备“查看会话”先展示已落库快照，再仅刷新该目标，失败保留离线快照，启动/all 不 fan-out。首库存落库屏障、4 分钟全快照恢复基线与持久化前 canonical Slot 会话投影可防止旧 Agent/Binding、强会话分行或 tombstone/suppressed 会话残留，并把每个动作路由回确切运行位置和会话副本。revision 增量补齐仍按阶段计划继续演进，当前不把定期全快照描述成增量协议完成，也不把本机定向回归描述成物理双机或公网长期可达验证。
- 零 Slot/零 Binding Agent 可在重启和跨设备目录快照后继续存在；新旧协议互通或目录权限不对称时不会发送未知目录消息，`inventory.read` 也不能越权删除、改绑或复活全局目录。远端首次准备在确认期间撤权、断连或替换连接后不产生本机副作用。
- SessionPointer、文件、屏幕和输入都遵守独立权限、目标端同意、大小上限和失败清理。
- TaskPackage 的错误密钥、篡改、类型伪装、重复路径、容量越界、目标冲突和重复导入都会在写入前停止；直送逐消息复核 feature/capability，拒绝、报错、撤销、TTL 和便携回退都清理受控暂存。Codex 原生导入保留根会话与内部记录并标注包内声明的来源，打开客户端失败不会回滚已保存内容。
- 公网信令不可用时局域网和已建立连接不受影响；诊断能区分 LAN、直连和 TURN 中继。
- 成品首次使用必须让同一个确切候选在一次性 userData 中连续经历首次初始化、重启恢复完成和完成后再重启，并确认零默认 Profile、零远端设备、零 Mesh 连接及进程/调试端点清理。
- 双 Mac 局域网库存、托管 runner 下载与物理用户安装分别记账。首个公开 Preview 仍需真实签名凭据、受保护环境、真实 Tag、匿名下载及浏览器 quarantine / Windows MOTW、SmartScreen、Defender、UAC 和物理干净机首启；只有稳定版全部门禁通过后，才能把有人值守 Personal Mesh 标记为公开稳定版本。

## 本轮精简（2026-09-14）

2026-09-26 本地融合继续保留这一精简边界。Claude CLI/DSH 可从所选运行位置打开隔离终端；DSH 采用官方 CLI 的 web 模板，不自动复制配置或凭据。待归属本机位置可仅移除登记。卡片支持长按/键盘排序、滚轮横向浏览和刷新保留位置，顺序只保存在本机；不引入 VHS 皮肤、不恢复排行和账本。当前验收范围与本地交付位置见 [验证记录](VALIDATION.md)。

普通新增选择名称和客户端，在本机创建独立环境并进入官方登录等待；既有个人或公司 API 环境从管理入口导入，接口/认证配置继续由既有配置工具或官方客户端负责。工作量排行、推断完成/陪伴账本、提醒总开关、庭院业务拖放及工具批量更新已退休；工作台使用 Agent 卡片，工具默认展示已安装项。活动按逻辑根与同设备真实来源去重，当前账号、总览和卡片额度共用可信度判断。验证与剩余真机门禁见 [VALIDATION.md](VALIDATION.md)。
