# 账号名片：把一张卡片导出成文件，别人拖进来后自己登录

> 状态：范围已由所有者在 2026-11-24 定下（见第 1 节）。排在 `docs/ARCHITECTURE_PLAN.md` 的九个阶段全部完成之后开发，并按整理后的架构来写。
>
> 名片里不带任何密钥、令牌或登录。基准第 3 节第 21 条（凭据不跨设备）原样不变，本功能不需要例外。

## 1. 要解决的事，和已经定下的

所有者要一个能发给组员的文件：拖进 AgentDesk 就在名册上出现对应的卡片和那只猫，组员自己登录。

已定：

1. 名片只带卡片本身的信息，不带登录。所有者原话：“那你可以做成后续他们自己登录，你先做吧，然后把这件事给我记好。”
2. 一个独立文件，同一个文件在 macOS 和 Windows 上都能用。
3. 文件名是卡片的名字；图标所有名片共用一个，带圆角的底，和应用图标一个画法（“图标就共用一个带圆角就行，因为它只是个文件嘛”）。
4. 由 AgentDesk 导出（“就从我这个工具里头导出就行”）。
5. 重复导入和各种极端情况要事先设计好（见第 6 节）。

关于有效期：所有者曾要求导出时可设有效期、最长 100 天。那是针对带登录的文件，为了防止文件留在聊天记录里被别人捡去用。名片不带任何秘密，捡到也只能得到一张需要自己登录的空卡片，所以不设有效期，少一个要维护的东西。所有者如果仍想要，可以按“导出时设 1 到 100 天、默认不限”加上，不影响其余设计。

组内多人用同一个服务的推荐做法，写进帮助：用服务商的团队版，由管理员邀请成员，每人用自己的席位登录；或者由管理员在服务商后台给每个成员各发一把接口密钥，成员在招募里自己粘贴。

## 2. 名片里有什么

| 带 | 不带 |
|---|---|
| 卡片名字、备注 | 任何密钥、令牌、密码、登录文件 |
| 客户端和形态（例如 Codex 命令行） | 本机的路径、数据目录 |
| 猫的样子：毛色、项圈、配饰 | 会话、对话内容、项目 |
| 接口类账号的非秘密配置：服务商标识、接口地址、模型名 | 任意环境变量、可执行文件、脚本、配置正文 |
| 名片编号、格式版本、导出时间、导出它的 AgentDesk 版本 | 导出人的设备、账号身份 |

哪些配置字段算“非秘密、可以写进名片”，由各家客户端的适配器用白名单声明；白名单之外的一律不写。

## 3. 文件

- 扩展名 `.agentdesk-account`，内容是带版本号的 JSON，人可以直接打开看。两个系统通用。
- 默认文件名是卡片名字，例如 `小橘.agentdesk-account`。两个系统都不允许的字符换成下划线；Windows 的保留名（如 `CON`、`NUL`）后面加下划线；过长的截断。文件名只是给人看的，导入时以文件里记的名字为准。
- 图标所有名片共用一个：圆角的米色底加那只猫，角上一个小名片记号，免得和应用本身混淆。由 `scripts/make-rounded-icons.js` 一并生成，安装时在两个系统上登记给这个扩展名。
- 装了 AgentDesk 的电脑上双击文件，打开 AgentDesk 进入导入。

## 4. 流程

**导出**（猫的档案里“导出名片…”）

1. 预览将写入的内容，一项一项列出。
2. 用系统的保存框存成一个文件。

**导入**（拖到名册上、双击文件，或在招募里选“名片”）

1. 先校验再做任何事（第 6 节）。
2. 预览：名字、客户端、猫的样子。接口类账号的**接口地址单独醒目显示并要求确认**：组员接下来会把自己的密钥交给这个地址，一张被改过的名片可以把它指向别人的服务器。
3. 没装客户端时卡片照常加上，状态“缺少客户端”，给出官方下载入口（沿用招募里现有的做法）。
4. 建独立的数据目录，卡片出现，状态“需要登录”。点一下走官方登录，或在档案里粘贴自己的密钥，都是现有流程。

## 5. 落在整理后的架构里

| 放在哪一层 | 内容 |
|---|---|
| `clients/<id>` | 适配器声明哪些配置字段可以写进名片、这个客户端在哪些系统上可用 |
| `core` | 名片格式的版本与逐级迁移；文件名清理 |
| `services` | 名片的组装、解析和校验，纯函数；导入的排队与事务；导入台账 |
| `commands` | `account.card.export`、`account.card.inspect`、`account.card.import`，各有“现在能不能做”和固定的原因码（第 6 节）。界面和命令行共用 |
| 存盘 | 导入台账用统一的存盘件，带版本：名片编号 → 建出的卡片、导入时间 |
| `ui` | 一个对话框，用公共的对话框外壳；拖入复用招募的拖放处理 |
| 主进程入口 | 双击打开文件（macOS 的打开文件事件、Windows 的启动参数、已在运行时转给已有窗口）统一交给 `account.card.import` 排队 |
| 打包 | 两个系统上登记文件类型、图标和打开方式 |

验收里固定包含：分层检查通过；适配器之外没有新增的按客户端名字的判断；三语词表一致；`ARCHITECTURE_PLAN.md` 第 8 节的各项指标不倒退。

## 6. 重复导入与极端情况

原则：先校验后动手；一次只处理一个导入；要么整张卡片建好，要么什么都不留；名片里的名字和备注是数据，永远不当路径或指令用。

| 情况 | 怎么处理 | 原因码 |
|---|---|---|
| 同一个文件再导入一次，上次建的卡片还在 | 不建第二张，选中已有的那张，说明“这张名片已经导入过”；另给一个明确的“仍然新建一张”，供同一个人要两个账号时用 | `card-already-here` |
| 同上，但那张卡片已被移除 | 当作第一次导入 | — |
| 两张不同的名片，登录后发现是本机已有的同一个账号 | 登录之前无从得知；登录后交给现有的身份归并规则处理（同一账号只是多一个位置，不多出一只猫） | — |
| 名字和已有卡片重名 | 沿用现有的重名处理 | — |
| 文件空、被截断、不是 JSON、不是名片、超过 64 KB | 拒绝，什么都不做 | `card-invalid` |
| 文件里有白名单之外的字段，或字段类型、长度不对 | 整个拒绝，不挑着读 | `card-invalid` |
| 文件里出现像密钥的值（被手工塞进去的） | 拒绝，提示名片不带密钥 | `card-invalid` |
| 版本比这个 AgentDesk 新 | 拒绝，提示更新 AgentDesk | `card-newer` |
| 版本较旧 | 按版本逐级迁移后读入；导出永远写当前版本 | — |
| 客户端是这个 AgentDesk 不认识的 | 拒绝，提示更新 | `client-unknown` |
| 客户端在这个系统上没有（例如只有 macOS 版的桌面端） | 拒绝，说明原因 | `client-unsupported-here` |
| 客户端没装 | 卡片照常加上，状态“缺少客户端”，给下载入口 | — |
| 猫的毛色或配饰是这个版本不认识的 | 用这个客户端的默认毛色、不戴配饰，照常导入 | — |
| 接口地址不是 https、带用户名密码、不是合法地址 | 拒绝，沿用现有的地址校验 | `card-invalid` |
| 一次拖进好几个文件，或连着双击好几个 | 排队逐个处理，最后一份汇总；一次最多 20 个，多出的提示分批 | — |
| 导入时正开着别的对话框，或应用还没启动完 | 先排着，就绪后再弹出导入预览，不打断正在做的事 | — |
| 应用没开时双击文件 | 应用启动，就绪后进入导入 | — |
| 应用已开时双击文件 | 交给已经开着的那个窗口，不开第二个 | — |
| 导入中途应用退出或崩溃 | 下次启动时清理没完成的那一次，不留半张卡、不留空目录 | — |
| 磁盘满、目录没有写权限 | 整个回退，提示原因 | `disk-unavailable` |
| 导出时文件名已存在 | 由系统保存框询问是否替换 | — |
| 导出到同步网盘等慢速位置失败 | 提示失败，不留下半个文件（先写临时文件再改名） | — |

导入台账只记名片编号和建出的卡片，不记文件路径和内容。台账丢失时退化为“当作第一次导入”，不会出错。

## 7. 分批

1. 名片格式、版本迁移、各适配器的字段白名单、导入台账。没有界面。第 6 节每一行一个测试；再加一个测试：任何账号导出的名片里都不出现密钥、令牌或路径。
2. 三条命令、命令行入口、导入的排队与事务、双击打开的接入。
3. 界面：档案里的导出、拖入与双击导入、预览与接口地址确认、各种提示。
4. 打包里的文件类型和图标登记；帮助里写组内共用的推荐做法；文档；不显示窗口的界面走查。

两个系统之间互传、双击打开、聊天软件里转发，要所有者在真机上实测；自动化测试覆盖不到。

## 8. 顺带发现，交给架构整理的第 3 阶段

现有的 Gemini 拖入导入写的是明文的 `oauth_creds.json`，而现在的 Gemini 命令行会把它迁进钥匙串或绑定本机的加密文件，实际行为和代码假设的不一样，需要复核。（来源：`docs/feature-evidence/A-credentials.md`）
