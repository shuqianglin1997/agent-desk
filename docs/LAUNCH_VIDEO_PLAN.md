# 发布短片：脚本与制作方案

> 状态：所有者 2026-11-24 看过示意版后要求做高质量最终成片（“写清楚脚本，设计好思路和细节，然后交给一个 Fable 5.2 extra 对话去做高质量最终成片”）。
>
> 示意版（脚本、配乐、画法的依据）：<https://claude.ai/artifact/RkP5aZxqbL53BDio1aEvWM>（第 9 版，页面上可切中文版 / English）。成片在它的基础上做，不推倒重来。

## 1. 要讲清楚的一件事

猫架（Catshelf）是电脑桌面上的一个中间管理台。每个 AI 还是在它自己的官方客户端里登录、对话、干活；猫架负责打开它们、看着它们的状态、把所有账号的对话记在一本账里，需要时帮着传话。它不代替任何客户端，也不存密码。

给谁看：手里有好几个 AI 订阅账号和接口的人。

每个痛点都要有自己的镜头：

| 痛点 | 镜头 |
|---|---|
| 账号一多，只能退出再登、轮流用 | 0–2 秒 |
| 对话散在各个客户端里，找不到、接不上 | 2–4 秒、18–24 秒 |
| 登录一次以后最好一直在 | 6–10 秒 |
| 同一个平台好几个账号，要同时开着 | 10–14 秒 |
| 看不出谁在忙、谁没额度了 | 14–18 秒 |
| 一个账号额度用完，要让另一个接着干 | 24–32 秒 |
| 想让一个 AI 叫别的账号分头干 | 32–40 秒 |
| 换一台电脑接着干 | 40–42 秒 |

## 2. 不能出现的

- “拖一个文件进来就多一只猫”这类会让人以为能把登录发给别人的镜头（账号名片已取消）。“拖进来”只拖一个数据目录，画面不出现文件名。
- 暗示猫架存密码、替客户端聊天、或自己发起调用。调度中枢是人在自己的 AI 对话里触发，猫架只中转。
- 任何品牌标志，以及模仿别家客户端的真实界面。
- 还没做的功能；任何真实账号、邮箱、路径、会话标题。

## 4. 文字与美术

**语言**：中文版只写中文，产品叫“猫架”；英文版只写英文，产品叫 Catshelf。真实界面用应用自己的中文或英文设置来录，不在画面上改字。

**字体**：
- 猫架界面、字幕、片尾用应用自带的像素字 Fusion Pixel 12px（`assets/fonts`，SIL OFL 1.1），只用 12 的整数倍。成片是 1080p，等于示意版的两倍：字幕 48px，片尾名字 144px，其余照比例。
- 别家客户端窗口和桌面用系统字，一眼看出那是另一个软件。

**字幕**：
- 一句一件事：中文不超过 12 个字，英文不超过 6 个词；同一时间只有一条。
- 要紧的词印成朱红。
- 样式像名牌：纸色底、深色边、左边一道朱红、右下投影；放在下三分之一、居中。
- 按拍子落下：三格台阶，最后回弹 2px（按 1080p 是 4px）。

**动效**：
- 位置落在 2px 格上（1080p 为 4px）。
- 先快后慢，一段 6–8 帧，只走台阶；落下回弹一次。
- 明暗只用台阶或网点，不用半透明淡入淡出。示意版关灯用了半透明压暗，成片要换成三档色或网点。
- 镜头在猫架窗口和整个桌面之间推拉，3–4 格台阶。

**颜色**：用 `src/pixel.css` 的 `--px-*` 皮肤色。

**信封**：只画真正经过猫架传递的东西（调用、发送到设备）；“复制”不飞信封，是红印加一张小条落进页脚。

**猫**：
- 用 `src/yard/cat-art.js` 的画法和动作，不另画。
- 平台看名牌、不看毛色：Codex、Cursor、Qwen、Copilot、OpenCode 有专属毛色，其余用家猫毛色。
- 名牌写“名字 · 平台”。

**别家客户端和桌面**：
- 别家客户端画成中性的通用窗口：标题栏写“平台 · 账号”，左边对话列表、右边对话、底下输入框，系统字，不画标志。所有者另给真实录屏时再换。
- 桌面是中性的一张：顶上菜单栏，底下一排程序坞，只写各客户端的名字。

## 6. 配乐与音效

- **配乐**：用示意版里的寄存器表（`Bgm.compose`），每分钟 120 拍，30 小节。
  - 1–2 紧张的小调；3 开灯一击。
  - 4–12 主题。
  - 13–16 复制：放慢成长音，25.0 秒那一拍全停，只剩一个往下掉的低音。
  - 17–20 调用：一条旋律 → 加鼓 → 加和弦 → 每拍一个重音。
  - 21–24 主题再现，加猫、换装时有重音。
  - 25 小锁“咔”一声后空着；26 关灯的摇篮曲；27–29 四个和弦各落一行字；30 最后一声。
- **合成**：用应用里的芯片发声器 `src/pixel/chip.js` 渲染。
- **音效**：用应用的音效表（`src/pixel/sfx.js` 里的名字）。时刻照示意版的音效表，敲字一个字一声。
- **混音**：峰值不超过 −1 dBFS，音乐和音效的相对音量照示意版。

## 7. 制作方法：质量和一致性第一

所有者 2026-11-24 补充：“不一定真实界面录制，关键是质量给高，尽可能一致，别为了录制弄得画风都变了”。

- **一套画风，全片统一**：猫架界面、桌面、别家窗口、片头片尾都在 1920×1080 上按同一套规矩画。猫架界面要和应用尽可能一致：同样的布局、`--px-*` 颜色、像素字、猫的画法与动作、真实的文案（取自 `src/i18n/zh.js` 与 `src/i18n/en.js`）。
- **真实渲染器是参考，不是必须**：可以用不显示的窗口跑真实界面（`scripts/hidden-electron-entry.js`）来对照布局、取元素位置和文字，或者在不改变画风的前提下直接用它的画面。只要录出来的东西会让画风变样（缩放发糊、字体不对、颜色偏、两种画法拼在一起），就改用自己画的。
- **内容必须真实**：画出来的每个状态，都要是应用真能出现的状态；功能、按钮、文案以应用当前的为准，不画还没有的功能。
- **鼠标**：成片里叠一个像素光标，点在元素真实的位置上。
- **编码**：本机没有 ffmpeg，也不下载。用 macOS 自带的 AVFoundation：用系统的 `swift` 写一个小程序，用 AVAssetWriter 把 PNG 帧和 WAV 写成 mp4。任何需要下载的步骤先停下来问。
- **音画同步**：按帧号算，第 n 帧对应 n/60 秒，切点与拍点误差不超过 1 帧。
- **不改产品**：制作用到的一切只放在 `media/launch-video/`。

## 8. 录制前要确认的

- **改名**：最终画面要等改名完成（`docs/RENAME_PLAN.md`）再录。可以先把整套流程做通，用当前构建试录。
- **仓库地址**：GitHub 上的仓库还叫 `agent-desk`。片尾写的是改名后的地址，发布前所有者要在 GitHub 网页上把仓库改名为 `catshelf`，否则片尾地址不对。
- **命令行**：“交给 AI”那一步显示的命令，以录制时应用里实际显示的为准。
- **“发送到设备”等状态**：画出来的样子要和应用里真实出现时一致；拿不准应用里长什么样，就用真实渲染器对照一下。

## 9. 验收

- 两版各 60.0 秒（±1 帧），1920×1080，60 帧。
- 每个切点落在拍子上；字幕不出画、不压住关键动作。
- 每帧没有真实账号、邮箱、个人路径。
- 先交中文版和英文版的 0–14 秒样片各一段，所有者点头后再做全片。

## 10. 不做的

- 不改产品功能和界面。录制需要的一切只放在 `media/launch-video/`。
- 不打开可见窗口、不启动客户端、不安装、不下载、不推送。
- 每一批做完、检查通过就提交（`AGENTS.md` 的“Commit as you go”），只提交明确的路径。

## 11. 15 秒短版和 README 循环动图

> 所有者 2026-11-25：“那你做吧，还是用Fable 5.2的Extra做。之前的视频里的各种我们之前讨论好的那种标准和要求，你别给弄没了，你别又重新给我弄一个特别水的视频出来。”

要在小红书、X、Hacker News 上推。信息流里视频自动播放、默认静音，所以前 3 秒猫就要动，不听声音也要看得懂。打动人的不是“多账号切换”，是两句话：谁在忙、谁没电，一眼看到；所有账号的对话，一本账。

一分钟成片不动。新做的两样只从成片现有的画法和状态里重新剪、重新排，不另起一套画风：第 2、4、6、7 节和 `media/launch-video/README.md`“和方案不一样的地方”照旧全部适用。

### 11.3 README 循环动图

一个猫架窗口，不动镜头、没有光标。架子上五个账号各在一种状态：一只敲键盘（1 条在跑），一只摞着纸冒汗（3 条在跑），一只睡着，一只在岗，一只没电摊平（能量格红，4%）。下面账本七行，四行在跑。4.5 秒第一只的对话回完，亮起“新回复”，它的猫头顶多一个信封；6 秒忙的那只有一条也回完了；7 秒、8 秒这两条在客户端里接着聊，又变回在跑，回到开头。

- **两句字幕**，各 4 秒：谁在忙，谁**没电**，一眼看到 / 你所有账号的对话，**一本账**（英文：Who's busy, who's **out**: one glance. / All your accounts' chats, **one ledger**.）。名牌样式不变，压在页脚上，不挡任何一行。
- **尺寸**：窗口画成 826×690，出图是它的两倍 1652×1380。README 里写 `<img … width="826">`：GitHub 桌面版 README 一栏宽约 830–880px，826 不会再被缩；高分屏上一个像素对一个像素，普通屏上正好二比一，手机上跟着栏宽缩小。
- **窄窗口是真实状态**：应用窗口没有最小宽度。用不显示的真实应用在 826 宽下对照过（`reference/capture.js`，`FILM_REFERENCE_SIZE=826x690`）：工具栏收成图标的那几档、表格各列的宽度规则（项目列占 22%）都照它。名牌宽度、标题标签不截断，沿用成片已经写明的两处不同。
- **首尾相接**：每只猫的动作在 8 秒里正好走整数遍，或者最后一帧接上和第一帧一样的一帧；“在跑”的三个点差 0.1 秒，看不出来。
- **真实**：正在写的对话不算“新回复”（`src/session-marks.js`），所以“新回复 → 又在跑”是应用里真会发生的变化。
- **睡着的那只坐第三个**：坐在最右边时它头上的“Z”会飘到“招募”上，坐第四个时英文版会压到“Quota overview”。

**GIF 是自己写的，不是 ImageIO 写的**：按原计划先用 macOS 的 ImageIO（和 mp4 一样用 `swift`）。它对这种大图每一帧都存整幅、各配一张自己挑的调色板：8 秒 10 MB，颜色还差几级。所以改成 `encode/gif.js` 自己写（Node，没有依赖，不下载）：整段一张调色板，第一帧整幅，之后每帧只存变了的那一块里变了的像素；画面没变的时刻并成一帧。结果 128 帧、约 180 KB。ImageIO 改用来读回核对（另外还用 Chromium 的解码器读一遍）。

**颜色**：GIF 最多 256 色。画面本身是平涂，多出来的颜色只在字的边缘和窗口左上角三个圆钮的平滑处。`tools/palette.js` 留下覆盖像素最多的 255 色，其余像素（万分之三）取最近的一色：平滑的边变成硬边，不加网点。
