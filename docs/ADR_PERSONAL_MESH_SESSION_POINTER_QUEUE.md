# ADR: SessionPointer 与本机密文队列

状态：Accepted for MVP implementation
日期：2026-08-10

## 决策

跨设备发送会话时，AgentDesk 只发送内部 `SessionPointer`，不发送会话正文，也不生成摘要、下一步或交接话术。面向人的“复制会话信息”继续使用同一个格式：路径和坐标。

Renderer 只能提交用户选中的 `conversationId + replicaId` 和目标 `deviceId`。Electron Main 必须重新从统一库存查到确切 `SessionReplica`，生成指针并加密；Renderer 不能提交来源路径、目标路径、密钥或网络消息。

目标设备离线时，发送任务保存在发送端本机 `mesh.db`。发送端再次与目标设备建立认证通道后自动重试。第一版不使用服务端离线邮箱。

## 指针与路径

每个指针绑定：

- 全局 Agent、账号绑定、本地 Slot、来源设备和确切副本；
- 稳定会话 ID、来源项目路径、来源会话文件与坐标；
- 可选项目 ID、相对路径和工作区版本；
- 创建时间、最长七天有效期和传输 ID。

来源绝对路径只作为显示元数据，不会在目标设备执行。项目未映射时，目标设备只能由 Main 打开系统目录选择器，让用户确认本机项目根；Renderer 不能提交一个任意 `localRoot`。相对路径必须拒绝绝对路径、盘符、UNC 路径和 `..` 穿越。映射完成后，收到的信息使用本机映射路径复制，坐标仍保留稳定来源标识。

## 加密与权限边界

指针 payload 使用 AES-256-GCM；密钥由当前 Mesh 的 OS 保护关联密钥通过 HKDF 派生，并绑定 `meshId`、传输 ID、类型、来源设备和目标设备。数据库与 peer Renderer 只接触密文，Main 只在已授权展示和接收路径中解密。

这保证本机队列和普通数据库不出现路径、坐标等明文，也防止密文被改投其他设备。它不是“目标设备独占解密”的公钥信封：当前 Mesh 内持有同一关联密钥的其他可信成员理论上也可派生密钥。因此：

- 当前方案只用于发送端本地队列和已经完成双向设备认证的直连通道；
- 不把该密文上传到服务端；
- 若后续实现服务端短期邮箱，必须先增加目标设备专用加密公钥、轮换和撤销设计，不能直接复用当前密文。

发送与接收继续受到 `session.pointer.receive` 权限、成员证书、签名信封、sequence、TTL 和连接目标校验约束。未知语义消息必须拒绝。

## 状态与限制

- 单次最多 50 条指针；
- 单个加密信封最大 400 KiB；
- 状态为 queued、sending、awaiting-ack、received、completed、failed、cancelled、expired；
- 接收端按传输 ID 幂等保存并返回确认；
- 发送中取消、过期和已完成状态不能被迟到的发送状态覆盖；
- 用户可以取消等待任务、重试失败任务；
- 收到的过期指针直接拒绝。

## 已验证证据

- 两个隔离 Mesh 数据目录完成在线发送、接收确认和项目映射；
- 目标离线时任务停留在本机密文队列，认证上线后自动送达；
- 数据库密文不包含来源项目路径或稳定会话 ID；
- 篡改标签、来源或目标后无法解密；
- macOS 与 Windows 风格根目录完成安全映射；
- 两个隐藏沙箱 Renderer 通过真实 WebRTC DataChannel 完成加密指针发送与确认。

## 尚未由本 ADR 证明

- 两台物理电脑长期离线重试；
- 服务端短期密文邮箱；
- 目标设备专用公钥信封和密钥轮换；
- 原始 transcript 或官方客户端会话迁移。

这些不影响 pointer-only 的本机队列，但不能被宣称已经交付。
