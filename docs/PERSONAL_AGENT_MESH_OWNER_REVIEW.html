Plain-language model

日常界面只需要理解三层。

内部可以有稳定 ID 和关联记录，但用户不应该每天操作四套技术对象。主界面只暴露 Agent、平台账号和运行位置；设备是筛选视角。

01

Agent

一个持续使用的工作身份。庭院的一只猫、经典名册的一张卡，都只代表它。

例：工作 Agent
02

平台账号

实际登录和额度的边界。一个 Agent 可以由用户明确关联多个平台账号。

例：Codex 工作号 + Claude 工作号
03

运行位置

动作最终落到的设备与客户端。打开、诊断、重扫、定位都必须选中一个准确位置。

What has to change

需要增加的功能，以及每一项改变什么。

下面不是功能名罗列。每一行都从当前问题落到完成态界面和用户得到的结果。

当前需要增加 / 改变用户最终得到
01
账号以本机 Profile 为主同账号跨设备会重复出现。
全局 Agent 目录Agent、平台账号、运行位置分层；可靠标识自动归并，其他情况由用户确认。
一只猫一个 Agent设备增加不会复制账号卡片。
02
只有本机视角无法快速知道其他电脑有什么。
顶栏设备视角增加“全部设备 / 某台设备”，并保留设备中心入口。
正交筛选设备只筛选，不改变 Agent 身份。
03
形态选择只在本机打开动作没有跨设备落点。
运行位置选择器原“形态”位置扩展为“Mac Studio / Codex CLI”等确切槽位。
动作不再猜打开、诊断、路径、重扫都有明确设备和客户端。
04
扫描文件直接变成会话压缩和 guardian 记录可能制造重复行。
逻辑会话索引用户根会话、压缩检查点、内部执行、设备副本分别建模。
一条对话始终一行压缩不再生成项目或会话。
05
只会复制本机定位另一台电脑不知道如何匹配项目。
复制 + 发送到设备复制仍只有路径和坐标；设备间另发结构化 SessionPointer。
人话仍简单不增加交接模板，目标设备可准确定位。
06
绝对路径只适合本机macOS 与 Windows 路径不同。
项目身份与路径映射同一项目在每台设备保存自己的根目录，传相对路径和稳定坐标。
跨系统继续工作目标设备本地解析，不执行来源绝对路径。
07
没有个人设备管理在线、资源、权限和撤销分散。
设备中心配对、状态、权限、资源、诊断、撤销删除集中管理。
设备是可选端口任意可信设备都能成为控制台，也都能被删除。
08
无法统一操作远端设备需要在各电脑之间来回切换。
独立远控控制台查看、多显示器、文件传输、输入控制分别授权；只允许一个输入目标。
能调动硬件但不误发主窗口不变成远程桌面。
09
删除范围不清楚空默认账号不能删，最后一个被强制保留。
位置 / 账号 / Agent 三种删除确认页明确影响；允许删到零，离线库存也不能让它复活。
目录真正归用户不自动补回 Claude、Kimi 等空项。

前端需要增加

  • 顶栏设备 Lens 与设备入口；不增加永久侧栏。
  • 全局 Agent 呈现、运行位置选择器、账号归属确认。
  • 跨设备会话位置列、复制主按钮、发送次按钮。
  • Agent 管理、三层删除、设备中心、项目映射弹层。
  • 主窗口第 6 行隔离远控工作区、输入目标提示、被控端常驻停止条。
  • 离线快照、权限缺失、版本不兼容等准确状态。

后端与本机能力需要增加

  • 设备密钥、成员证书、配对与撤销事件。
  • Agent 目录、账号关联、会话身份和项目映射存储。
  • 加密库存同步、SessionPointer、文件传输队列。
  • 信令、STUN/TURN、P2P 连接和断线恢复。
  • macOS / Windows 屏幕采集、输入、权限与紧急停止。
  • 严格语义 API；不接受远程 Shell、任意路径或命令。

End-to-end workflow

一个人从添加设备到继续会话，完整过程是这样的。

这条路径把前面的模型和界面串起来。每一步只有一个明确目的，不把设备连接、账号整理和任务交接混成一件事。

01

在 MacBook 创建 Personal Mesh

本机生成设备身份和恢复材料；现有本机账号按当前关系迁入全局目录，不移动任何文件。

结果：本机继续可用，设备列表目前只有 MacBook
02

添加 Mac Studio 与 Windows GPU

短码只帮助会合，双方核对安全指纹，并分别设置目录、文件、屏幕和输入权限。

结果：两台设备成为可信执行端，但不会自动获得全部权限
03

确认新设备上的账号关系

同一 Codex 工作号自动增加位置；无法确认的 Claude 账号选择“工作 Agent 的另一平台账号”。

结果：庭院仍是 3 个 Agent，不因设备增加复制猫
04

从“全部设备”查看个人完整状态

庭院展示去重 Agent；控制条显示运行位置；会话表汇总所有设备索引，离线记录标记采样时间。

结果：从任意可信设备都能看见同一份个人工作目录
05

搜索并选择 AgentDesk 会话

会话发生过 5 次压缩并产生 10 个 guardian/subagent 文件，列表仍只有一条 C-01。

结果：用户选的是逻辑对话，不是内部物理文件
06

复制信息或发送到另一台设备

发给人时复制路径与坐标；发给自己的设备时发送结构化 SessionPointer，不生成交接话术。

结果：人能直接说明，机器能准确定位，两种语义不混淆
07

目标设备解析自己的项目路径

Mac Studio 的 /Users 路径和 Windows 的 D:\Projects 路径都绑定到同一个项目身份。

结果：目标端本地解析，不执行来源设备的绝对路径
08

需要时打开远控，结束后返回会话

GPU 工作只替换原窗口第 6 行；明确当前输入目标，发送选定文件，完成后停止输入、断开或返回会话。

结果：硬件可以被充分调动，主界面仍专注 Agent 与会话
When something changes

常见异常不靠猜，系统直接给出对应处理。

这些情况决定产品是否真的好用。每一项都要在界面中说明发生了什么、用户能做什么、系统绝不会偷偷做什么。

OFF

目标设备离线

继续展示最后会话索引和采样时间；打开、重扫、远控等副作用动作禁用。SessionPointer 可以进入本地等待队列。

用户操作：仍可复制定位，或等待设备上线后发送。
ID

同一 Profile 退出旧号、登录新号

运行位置进入“登录已变化”，暂停继续归入旧账号。历史会话不按当前登录批量改名。

用户操作：选择已有登录、已有 Agent 的另一账号或全新 Agent。
CP

会话发生上下文压缩

只增加内部 checkpoint 数量；项目、会话 ID、列表行和复制入口全部保持不变。

用户操作：无需处理，继续使用原会话。
SUB

产生 guardian / subagent 文件

内部记录挂到父会话的诊断谱系，默认搜索、计数和列表都不显示；父记录暂缺时也不提升成用户会话。

用户操作：普通使用无需处理，诊断时再展开。
MAP

目标设备没有项目路径映射

系统展示来源项目和候选仓库，要求用户选择一次本地项目根。目录同名不能直接算同一项目。

用户操作：确认本地根目录；以后复用这条映射。
DUP

两个 Agent 被错误分开或合并

合并 Agent 会预览账号、设备和会话数量；拆分则把指定账号或位置移到新 Agent。两者都不移动官方数据。

用户操作：在 Agent 管理中显式合并或拆分，并可短期撤销。
DEL

已删除 Agent 被离线旧库存再次引用

删除记录优先于旧库存，远端位置保持 suppressed / 待归属，不能自动让 Agent 复活。

用户操作：只有主动重新添加时才重新决定归属。
NET

直连失败或网络切换

先冻结输入，重新进行连接协商；可以安全回退 TURN 时明确标记“中继”，全部失败则显示具体原因。

用户操作：选择继续中继、重试或断开，不会看到笼统“连接失败”。
Backend & data boundary

跨设备连接不等于把个人数据搬到云端。

后端只解决设备会合、短期在线状态和必要中继；设备授权、Agent 目录和业务内容仍由用户自己的设备控制。

始终留在来源设备

这些数据不因为加入 Personal Mesh 就自动同步。

第三方账号密码、Cookie、Token
官方客户端账号数据库
完整会话正文与原始 transcript
项目目录与未选择的文件
设备私钥和 Mesh 关联密钥

可信设备间端到端传递

只同步管理和定位所需的最小内容。

全局 Agent 目录与安全关联结果
设备状态、运行位置、额度来源快照
只读会话索引与项目映射
显式 SessionPointer 与选定文件
屏幕媒体与临时输入事件

最小后端可见

服务端帮助会合和中继，但不能成为设备授权者。

设备公共标识与在线租约
一次性邀请摘要与连接信令
签名撤销事件与协议版本
短期 TURN 凭据与使用量
容量指标和不含业务内容的错误码
控制设备 A界面、目录缓存、用户授权、当前操作目标
⇄
信令 / STUN / TURN帮助发现与连接；中继只转发加密包
⇄
执行设备 B本地重新查 ID、检查能力、解析路径、执行固定语义动作
允许的远端动作

打开已登记账号、聚焦已知会话、接收定位、接收文件、查看屏幕、控制输入。

明确不允许

通用 Shell、任意命令、任意 URL、任意绝对路径、后台安装软件或修改系统权限。

本机始终有最后决定权

权限不足、设备锁定、用户停止、证书撤销或版本不兼容时，危险能力直接失败关闭。

Build order

开发顺序必须先把身份和会话做对，再上远控。

如果先做远程桌面，会得到一个能看屏幕但仍然管不清 Agent 的工具。下面每一阶段都有清楚的退出条件。

PHASE 1
技术验证与 ADRElectron 中的 WebRTC 承载、两设备认证、STUN/TURN、系统权限、存储与打包。
隔离验证，不改主产品流程。
两台真机认证数据通道成立
PHASE 2
全局 Agent 与设备中心Device、Agent、平台账号、运行位置、关联纠错、删除记录、配对与撤销。
主界面增加设备 Lens，不改七行骨架。
同账号跨设备只显示一次
PHASE 3
正确的会话身份与跨设备索引先修 Codex/Claude 根会话、压缩、内部分支，再同步逻辑会话和副本。
全部设备 / 单设备 × 当前 / 全部 Agent。
压缩不增加项目或会话行
PHASE 4
复制、发送与项目映射SessionPointer、发送到设备、跨系统项目根、离线本地队列。
复制格式完全不变。
不同根路径能安全定位
PHASE 5
选定文件传输manifest、哈希、分块、背压、续传、磁盘检查、取消与安全清理。
不自动同步整个项目。
失败可重试且不留残缺文件
PHASE 6
远程仅查看独立窗口、屏幕权限、多显示器、自适应画质、直连/中继状态、被控端提示。
还不能注入键鼠。
macOS / Windows 双向可看
PHASE 7–8
输入控制与多设备控制台鼠标、键盘、IME、唯一输入目标、按键释放、紧急停止、低频缩略图。
一个高质量流，其他设备低频观察。
切换设备不会误发输入
PHASE 9
无人值守独立评审系统服务、开机启动、锁屏策略、安装版、恢复和更高安全标准。
不随前面阶段默认开启。
必须再次由所有者批准

A

产品主轴

单人 Personal Mesh；Agent 是全局管理对象，设备是筛选轴，运行位置是动作落点。

决定同一账号跨设备是否只出现一只猫，以及所有动作是否能准确定位。
B

会话身份

一行代表一条逻辑对话；压缩是内部检查点，guardian/subagent 是隐藏分支，项目独立解析。

决定“压缩后多出会话/项目”的问题能否从根上消失。
C

第一阶段范围

先做设备、全局 Agent、正确会话索引、复制/发送和路径映射，再做查看与控制。

决定首个可用版本先解决工作连续性，还是先变成普通远程桌面。
D

权限与数据

不跨设备同步凭据；目录索引、文件、屏幕、输入和无人值守分别授权；不提供任意命令。

决定 P2P 协议、后端可见内容和产品整体安全边界。
E

主界面契约

七行骨架不动；设备 Lens 与 Agent 范围独立；复制会话信息仍是唯一主按钮且只含路径/坐标。

决定现有日常工作流是否保持稳定，以及新增能力会不会挤乱主界面。

完成版本的验收清单

Agent、账号与删除

  • 同一实际账号登录多台设备时，只出现一个 Agent、一只猫。
  • 同一设备多个实际账号保持独立，不按名称或平台误合并。
  • 跨平台账号只能由用户明确关联到同一 Agent。
  • 所有动作都能回到一个准确设备和客户端位置。
  • 位置、账号、Agent 三种删除范围清楚，均可删到零。
  • 离线旧库存不能复活已删除 Agent，也不会自动补默认平台项。
  • 同一账号额度不会因多设备快照重复相加。

会话、项目与复制

  • 任意次数上下文压缩仍是一条逻辑会话和原项目。
  • guardian、subagent、sidechain 默认不进入列表和计数。
  • 物理文件、逻辑会话和项目数量可以分别核对。
  • 多设备副本只在有强标识或明确来源链时折叠。
  • 打开、复制和发送前始终有明确会话副本。
  • 复制会话信息始终只有路径和坐标。
  • 跨系统项目路径在目标设备本地安全映射。

设备、连接与远控

  • 用户可以添加、重命名、撤销和删除任意远端设备。
  • 任意可信设备都可以成为当前控制台，没有永久主机。
  • 离线设备只显示有时间的最后快照，不能执行副作用动作。
  • macOS 与 Windows 可以双向查看和控制。
  • 直连失败时可以安全回退加密中继，并在界面明确标记。
  • 同时观察多台设备时只有一个输入目标。
  • 被控端始终可见并能立即停止；断线释放全部按键。

安全、兼容与恢复

  • 密码、Token、Cookie、原始平台账号 ID 不跨设备同步。
  • 信令与 TURN 不能解密目录、屏幕、文件或会话定位。
  • 没有通用 Shell、任意命令、任意 URL 和远端绝对路径执行。
  • 主窗口七行骨架、庭院/经典和账号基础工作流不被破坏。
  • 禁用 Mesh 后，本地 AgentDesk 仍可独立使用。
  • 配对撤销、网络切换、传输失败、权限撤销都有明确恢复路径。
  • 版本不兼容时危险能力失败关闭，不静默降级授权。

不改变核心模型的四个可调参数

离线投递先用发送端本地队列；之后再审是否增加短期端到端密文邮箱。
审计保留当前建议本机滚动 30 天，允许用户手动清空。
容量预算20 台配对、8 台在线、4 台远控、1 个高质量输入目标。
无人值守默认不做；安装版、系统服务和恢复方案成熟后独立批准。
