# ADR: 用户选定文件的加密分块传输

状态：Accepted for MVP implementation
日期：2026-08-10

## 决策

AgentDesk 只传输用户在系统文件选择器中明确选中的普通文件。不接收 Renderer 提交的来源路径或保存路径，不递归发送目录，不跟随符号链接，也不自动同步项目。

发送端 Main 先把每个文件复制到 AgentDesk 自己的私有暂存目录，并在同一次读取中计算 SHA-256。后续重试始终读取这份固定副本，避免原文件在排队期间改变后被静默发送成另一份内容。原始文件永远不移动、不改写、不删除。

目标端先收到加密 manifest，只看到待接收提示。用户点击接收后，由 Main 打开系统目录选择器；目标路径不能来自 Renderer 或远端消息。已有同名文件不会覆盖，AgentDesk 使用稳定后缀生成新文件名。

## 协议

1. `file.offer` 发送加密 manifest：文件安全名称、大小、全文件 SHA-256、有效期和传输 ID。
2. 目标端确认本机保存目录，检查可用空间，在该目录创建只属于本次传输的隐藏临时目录。
3. `file.accept` 返回每个 `.part` 文件已经可靠写入的字节偏移。
4. 发送端从这些偏移继续，以 96 KiB 原始块发送 `file.chunk`。
5. 每块单独使用 AES-256-GCM 加密并绑定 Mesh、传输、来源、目标、文件序号和偏移；peer Renderer 只看到密文。
6. 目标端校验块哈希、偏移和大小，写入并同步到磁盘后返回 `file.chunk.ack`。发送端收到确认后才发送下一块，形成明确背压。
7. 每个文件完整后再次计算全文件 SHA-256；全部通过后使用不覆盖目标的硬链接或排他复制完成落盘，再返回 `file.complete`。

DataChannel 保持可靠有序，但应用层仍保留块确认和偏移恢复，不能把“消息已交给 Renderer”误当成“目标磁盘已经写入”。

## 限制与安全边界

- 单次最多 32 个文件；
- 单文件最多 4 GiB，单任务最多 8 GiB；
- 分块原始大小 96 KiB，低于 peer 信封 512 KiB 上限；
- 开始暂存和接收前检查磁盘空间，并保留 64 MiB 安全余量；
- 拒绝目录、符号链接、重复来源、NUL、路径分隔符、Windows 危险文件名和越界目标；
- 文件名和目标目录只存在于端到端密文或本机加密状态文件，不进入普通数据库审计；
- `file.receive` 默认关闭，两台设备都必须明确允许；
- 发送端离线队列和已认证直连沿用 Mesh 关联密钥派生密文，不上传服务端；未来服务端邮箱不能复用该方案；
- 成功后清理发送暂存副本和接收 `.part`；取消发送只删除 AgentDesk 创建的发送副本；取消接收保留隔离的 `.part` 以避免误删可恢复数据，绝不删除已完成用户文件。

## 恢复语义

- 连接中断后，发送任务进入失败或等待状态；
- 重新认证连接时再次发送 offer；
- 已选择保存目录的目标端自动读取 `.part` 实际大小并返回偏移；
- 重复块只有在已有字节内容完全相同时才确认；交叠、缺口或内容不同立即失败；
- 校验失败的 partial 会改名保留诊断，不会成为最终文件；
- 迟到的 complete、cancel 或 error 不能覆盖已经完成、取消或过期的终态。

## 已验证证据

- 240 KiB 以上文件跨三个块传输，第一块确认后模拟断线，再从 96 KiB 偏移恢复并完成；
- 目标目录已有同名文件时保留原文件，新文件使用 `(2)` 后缀；
- manifest、本机保存目录和文件内容在普通数据库/状态文件中均不可见；
- 两个隐藏沙箱 Renderer 通过真实 WebRTC DataChannel 传输 184,333 字节文件并完成全文件比对；
- SessionPointer、文件传输与库存同步继续共享认证信封，但文件块使用逐块背压，不形成无界队列。

## 尚未由本 ADR 证明

- 两台物理电脑跨 NAT 的大文件和长时间恢复；
- Windows 文件被杀毒软件、索引器或其他进程占用时的全部组合；
- TURN 中继下的带宽整形；
- 服务端离线文件邮箱；该能力仍明确不做。
