# 搭配 AgentDock 使用 AgentDesk

AgentDock 负责准备代理服务与客户端配置；AgentDesk 管理各账号的运行入口和本机会话。两者共同使用时，账号的配置目录与启动环境需要保持一致。

## 账号打开

- 在 AgentDesk 中为不同账号使用各自的配置目录；打开前确认选择的是正确账号和运行位置。
- Claude Desktop 使用所选账号的数据目录，避免继承命令行代理、认证及模型变量而误用其他账号配置。
- Claude CLI 从账号入口在终端打开，使用自己的配置根；工具中心仅为匹配的 CLI 槽位带入账号环境，选择无关桌面账号时仍可打开普通工具，不借用其他账号的目录。
- DSH 可作为已安装命令行工具被发现并打开。独立目录只创建空根，不从默认目录复制配置、代理或凭据；客户端仍需用户完成其自身配置。本次不增加 DSH 公司与个人账号自动拆分流程。
- DSH 账号入口固定使用 `--profile web`，由 DSH 在该 `DSH_HOME` 首次初始化内置模板；不使用桌面专属 `desktop`。依据为 [官方 CLI reference](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md)。本机未安装 DSH，本批只验证发现、参数、环境和空目录行为，不声称真实服务或账号登录已通过。

## Claude 第三方入口仍显示登录页

PR #2 提供者报告的排障案例是第三方客户端读取的配置目录与登记目录不一致，涉及带 `-3p` 后缀的第三方配置根。本批未重新验证该客户端版本，不能把这个案例作为通用约定。应在备份后确认 AgentDock 准备的位置与实际客户端读取位置，不对所有账号自动追加后缀或自动迁移目录。

该配置排障与 AgentDesk 的启动环境修复是两层工作。AgentDesk 不包含代理地址、公司模型映射或免登录凭据，也不会绕过客户端登录。

## 清理遗留入口

不再使用的待归属本机运行位置可以直接移除登记。确认后保留所属 Agent、其他位置以及原有会话文件；重启后不再重复提示已移除位置。需要再次使用时可重新登记原目录。
