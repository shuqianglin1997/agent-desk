# 调度中枢实施规划

> 状态：所有者已于 2026-11-24 批准开启，并明确了边界。本文是实施细化；`docs/PERSONAL_AGENT_MESH_PLAN.md` 仍是单一基准，两者冲突时以基准为准，并把差异写回基准的变更记录。
>
> 第 1–5 批已在本地实现：桌上的动效按所有者批准的“动效总览”，档案里的两个开关、系统页的文件夹与上限、第 8 节的说明纸条按所有者批准的原型（2026-11-24“可以，照做”）。见第 9 节。第 2 节的边界不能松。

## 1. 是什么

登记在 AgentDesk 里的账号，除了由用户点“打开”，还可以被用户自己的 Agent 借用：用户在某个 Agent 的对话里说一句话（例如“用我的 Codex 工作号检查一下这份改动”），那个 Agent 通过 AgentDesk 的命令行看到名册、挑一个账号、让它在后台跑一段对话，再把结果取回来。

AgentDesk 在这里只做两件事：中转这次调用，记录它的标题和状态。

## 2. 边界

所有者的原话：这是人在自己的 Agent 对话里触发，通过这个工具中转去调用的；工具本身并不会去调用，它只是一个中转平台、信息管理平台。由此定下：

1. **发起的永远是人。** AgentDesk 自己从不发起、不排队、不重试、不定时、不替用户挑账号，也不把一段对话的结果自动喂给另一个账号。没有一次明确的调用，就没有后台对话。
2. **一次调用就是一次中转。** 一个确切的账号、一段提示词、一个工作目录、一个标题。AgentDesk 不改写提示词，不读取或总结对话内容来做决定。
3. **只有允许被调用的账号才出现。** 每个账号在档案里有一个开关“允许别的 Agent 调用它”，默认关。没打开的账号不出现在名册里，也不能被调用。
4. **不接受任意命令。** AgentDesk 用每个客户端固定的无界面运行方式启动它（参数由适配器写死），调用方只能给名字或编号、标题、目录和提示词。提示词走标准输入，不走命令行参数。
5. **工作目录要事先允许。** 只能是用户在 AgentDesk 里允许过的文件夹；默认只读，要让被调用的账号改文件，需要在档案里单独打开。
6. **防止层层套娃。** 被调用的 Agent 再调用别人最多两层（用环境变量传层数）；同时运行的后台对话有上限；同一个账号一次只跑一个。
7. **额度看得见。** 调用消耗的是被调用账号的额度；电量见底的账号拒绝新调用，并说明原因。
8. **密码和令牌不经过 AgentDesk；只在本机。** 跨设备调用不在这次范围内。
9. **界面只显示标题和状态。** 默认不显示对话内容；用户点开时沿用现有的会话阅读。每条记录都可以由用户停止。

这改写了基准 5.2 节里“自动控制 Agent 对话生命周期”这一条的写法：AgentDesk 仍然不自动控制、不自动安排；允许的只是把用户自己的 Agent 明确发起的一次调用中转过去，并记录它。

## 3. 命令（成品命令行）

| 命令 | 做什么 | 返回 |
|---|---|---|
| `agents list` | 列出允许被调用的账号 | 名字、编号、平台、是否就绪、电量档位。不含任何秘密 |
| `run --agent <名字或编号> --title <标题> --cwd <目录>` | 让那个账号在后台开一段对话；提示词从标准输入读 | 任务编号，立刻返回 |
| `runs status --run <编号>` | 查询状态 | 启动中、运行中、已完成、失败、已停止，以及用时 |
| `runs output --run <编号>` | 取最后的回答 | 被调用账号给出的最终回复 |
| `runs list` | 最近的后台对话 | 标题、谁叫的、叫了谁、状态 |
| `runs stop --run <编号>` | 停止 | 确认已停止 |

名字就是名册里猫的名字，要求唯一；重名时命令返回候选并要求用编号。调用方是谁，由它启动时带的标签说明（例如 `--from "Claude 个人"`），只用于显示，不当作身份凭证。

所有命令在桌面实例锁下执行，输出与错误沿用 `docs/AI_INTERFACE.md` 的约定。

## 4. 界面

- 账本里多一种记录：后台对话。每条显示标题、谁叫的谁、状态灯、用时，旁边有“停止”。
- 状态灯：排队中是空的；运行中一闪一闪；已完成是绿的；失败和已停止各有各的样子。
- 被调用的那只猫在跑的时候是“干活”，跑完跳一下；从睡着被叫起来时先“醒来”。
- 猫的档案里多两个开关：“允许别的 Agent 调用它”和“允许它改文件”，都默认关。
- 系统页里多一处：允许的工作目录、同时运行的上限。

## 8. 三个动作的说法与悬浮说明

所有者指出界面上有几个意思相近的词，要梳理清楚，并在鼠标指上去时给出说明，或者配一行小字。梳理的结果是三个动作，界面、命令行、文档和宣传材料都用同一套说法：

| 动作 | 是什么 | 谁做 | 对话去哪了 | 界面上的入口 |
|---|---|---|---|---|
| 复制 | 把一段对话的位置（路径和坐标）复制出来，贴给另一个 Agent，它自己去读 | 人 | 没动 | “复制会话信息”（仍是会话区唯一的填色主按钮，复制出来的格式不变） |
| 交接 | 把整件事搬到另一台电脑或另一个人那里接着干 | 人 | 搬走一份，原来那份不动 | “送出”里的“发送到设备”（只送位置）和“交接任务”（打成一个包：对话、代码改动、备注） |
| 调用 | 你的 Agent 让另一个账号在后台跑一段对话，把结果拿回来 | 人对自己的 Agent 说一句话，那个 Agent 通过 AgentDesk 中转 | 没动，还在你正在聊的那个 Agent 那里 | 账本里的后台对话记录；档案里的“允许被调用” |

**同一台电脑上换一只猫接着干，用的是“复制”**：人复制、人贴过去。AgentDesk 不提供“把对话直接塞给另一只猫”的动作。只有“调用”时，内容才由 Agent 通过 AgentDesk 自动送过去。

要做的：

- 每个入口鼠标指上去（或键盘聚焦）时出现一个说明浮层，用一两句话说清“这是做什么的、对话会不会动、会不会离开这台电脑”。浮层用应用自己的皮肤，进入顶层，不被面板裁掉；遵守“读的字与看的字”的规则（标题点阵字，句子正文字体）；键盘可达；减少动态效果时直接出现。
- 菜单里空间够的地方，在每一项下面配一行小字说明，不必等鼠标停上去。
- “送出”菜单里的两项要让人一眼分清：一个只送位置，一个送整件事。
- 三种语言同时补齐。说明文字先出原型给所有者看。
- `docs/PRODUCT.md` 里加一段词表，写清这三个动作。

说明文字的初稿：

- 复制会话信息：复制这段对话的位置。贴给另一个 Agent，它就能自己读到。对话本身不动。
- 发送到设备：把这段对话的位置送到你的另一台电脑。只送位置，不送内容。
- 交接任务：把整件事打成一个包——对话、代码改动、你写的备注——交给另一台电脑或另一个人。原来这份不动。
- 后台对话：你的 Agent 通过 AgentDesk 让这个账号在后台跑的一段对话。这里只显示标题和状态。
- 允许被调用：打开后，你的其他 Agent 可以通过 AgentDesk 让它在后台干活。AgentDesk 自己不会调用它。

## 9. 实施记录

2026-11-24，第 1、2 批在本地实现（未提交），验证见 `docs/VALIDATION.md`。命令行的写法与边界见 `docs/AI_INTERFACE.md` 的“调度中枢”。与上面各节不同、或上面没写清、实现时定下的地方：

- **“排队中”改为“启动中”。** AgentDesk 不排队：账号正在跑（`agent-busy`）或到了同时运行的上限（`run-limit`）就直接拒绝。第一种状态只表示“收到了、客户端还在起来”。
- **开关放在账号上。** “允许别的 Agent 调用它”“允许它改文件”是每个 Profile 的 `hub` 字段，默认关，只能在桌面窗口里改；命令行没有改开关、加文件夹、改上限的命令，别的 Agent 不能给自己开权限。不支持后台运行的客户端打不开这个开关。名册里的名字是猫的名字（有本机 Agent 目录时取目录里的名字，没有时取同一身份组的代表名）。
- **Codex 账号用同一个账号目录里的 Codex 命令行。** AgentDesk 里的 Codex 账号就是一个 `CODEX_HOME`，桌面版和命令行共用它，所以 Codex 账号只要找得到 Codex 命令行就能被调用；Claude 桌面版的目录不是 `CLAUDE_CONFIG_DIR`，仍然不能被调用。
- **需要桌面在运行。** 子进程由桌面 Main 监管；桌面没开时 `agents list`、`run`、`runs stop` 返回 `desktop-not-running`，`runs list/status/output` 只读已结束的记录。桌面意外退出后，下一次读到还写着“运行中”的记录会改成“失败 · 意外退出”。
- **层数。** 人自己的 Agent 没有 `AGENTDESK_HUB_DEPTH`，算 0；它叫的后台对话是 1；那一个再叫的是 2；第三层被拒绝。值读不懂时按 2 算（宁可拒绝）。
- **电量。** 可信额度（同卡片上的能量格）不足 10% 或已触发限额时拒绝；额度未知不拦。是否登录用文件判据，只有确定没登录才拒绝（钥匙串里的登录算未知）。
- **提示词与回答。** 提示词最多 64 KiB，只从标准输入读，和密钥一样只在单实例消息的内存里交给 Main；回答在这次桌面运行期间留在内存，之后从该账号自己的会话记录读回最后一条回复。AgentDesk 的文件里只有标题、调用方标签、目标、状态、时间和会话记录的位置。
- **退出与移除。** 退出 AgentDesk 时先停下所有后台对话（不看“保留客户端”的设置），再走原有的关客户端流程；移除账号会停下它的后台对话。关掉“允许被调用”不会停下正在跑的那一段，人可以自己点停止。
- **Claude 命令行的写法。** 官方文档只写了 `cat file | claude -p "query"`，没有写只用管道，所以查询参数是一句固定、不含内容的引导语，提示词原样走标准输入，不改写。只读用 `--permission-mode dontAsk` 并去掉 `Edit,Write,NotebookEdit`（需要批准的调用一律拒绝，只读的命令照常），可写用 `acceptEdits`。
- **Codex 的写法。** `codex exec --json --color never --sandbox read-only|workspace-write --skip-git-repo-check -`。文件夹是人在 AgentDesk 里允许过的，所以跳过 Codex 自己“必须在 Git 仓库里”的检查。官方页面对 exec 的默认沙箱说法不一致，所以每次都写明。

### 第 3 批：桌上的动效（2026-11-24）

所有者看过“动效总览”（https://claude.ai/artifact/7CpZYmhyCABpVRNsstCPsW）后批准照它做进应用，它取代了先出原型的要求，是这部分的视觉依据。已做：调用开始、运行中、一只叫几只、完成并交回、失败、你叫停、台面外来的调用，以及复制、发送到另一台电脑、收到别处送来的。复制沿用已有的盖印和飞进页脚，不演“对方收到”。

- 状态由 Main 在每次变化时推给界面（`hub:changed`），界面不轮询。
- 发起方是哪只猫：只认 AgentDesk 观察到的事实——它中转的上一段对话，或发起的进程就在某个已登记账号的目录里（环境变量里的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 等恰好对上一个账号）。都不是时信封从桌子边缘进来，`--from` 只加引号当标签显示。
- 点线画在搁板的木板上：总览里画在猫头顶，但应用里那一带和 Agent 区的标题行重叠，所以下移到猫脚下的木板，颜色用木板上的亮色。
- 同时叫着两只以上的那只戴上领结；被叫的在跑时一律“干活”，结束后十五秒内按结局显示（完成在岗、失败在岗、停止揣手），之后回到按活动推断的样子。
- 声音用已有的：台面上的一只叫另一只是“送出”，台面外来的是“到达”，交回是“好了”，失败由红字状态行带出“出错”；停止是你自己点的，不另响。
- 一封信 12 步、约一秒、先快后慢、落在 2px 的格子上；同时最多三处；窗口不在前台、系统要求减少动态效果时直接显示结果；任何真实的点按或按键让飞着的东西立刻落地。

### 第 3、6 批：由人来定的三处（2026-11-24）

所有者看过可操作的原型页（https://claude.ai/artifact/F5AXuirVQn15E2Jj1QbUcA）后回复“可以，照做”。三处都照原型接进应用，中英日三种语言同步。

- 猫的档案多一段“调用”，在“账号”和“送走”之间。它跟着位置段里展开的那个位置走：标题旁写调用方用的名字（与 `agents list` 名册里的名字同一来源）；两个开关“允许别的 Agent 调用它”“允许它改文件”，后者只有前者开着时才能开；下面一两行说明：用哪个命令行跑、同名时调用方得用编号、还没有允许的文件夹。客户端不能被调用时两个开关都不可用，并写明原因：只能开窗口的桌面版、提示词只能写进命令参数的、没有可靠只读设置的，各有一句；还没核对过的客户端是“还在核对”。远端位置不显示这一段，因为调用只在这台电脑上。开关先按人点的样子显示，Main 存好后以它返回的为准，没存上就退回原样并在页脚说一声。
- 系统页“设置”栏里，“退出时”下面多一块“后台对话”：允许干活的文件夹（“添加文件夹…”打开 Main 的系统选择框，界面只送编号，移除按编号）和同时运行的上限（1–4）。
- 说明纸条：复制会话信息、送出里的发送到设备与交接任务、账本里“后台对话”的标签、档案里的“允许被调用”。鼠标停一下或键盘聚焦时出现：标题、一句话、三件事（谁做、对话动不动、离不离开这台电脑）。按钮不可用时也看得到，最后一行写真正的原因（还没选会话、交接一次只能一条、只能交接这台电脑上的、没有另一台电脑、要先选操作来源）；纸条开着时收起按钮自己的原生提示。Esc 只收起纸条，不连带关掉下面的菜单或档案。送出里的两项各配一个图标和一行小字（只送位置；送整件事：对话、改动、备注）。
- Main 的 `hub:state` 多了 `accounts`（每个本机账号的编号、调用方用的名字和两个开关，不含路径或登录信息）和每种客户端实际运行的命令行名称。
