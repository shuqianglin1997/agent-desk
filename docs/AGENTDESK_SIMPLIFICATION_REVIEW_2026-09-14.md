# AgentDesk 功能精简评估与实施建议

日期：2026-09-14  
评估基线：`main` / `3a4919a14c05e4db1c828cccad3ec9e024023efe` / `0.10.1-preview.1`  
状态：**所有者已批准，本轮本地实施完成；不推送。实施基准已同步至 Personal Agent Mesh 1.34。**

下文第 1–7 节保留精简前的评估与后续分期；代码量、缺陷复现及源码链接均指评估基线。当前结果见第 8 节及 [验证记录](VALIDATION.md)。

## 1. 判断

AgentDesk 最有价值的主线是：**让一个人稳定使用多个 Agent 账号，找到正确会话，在明确的账号环境和设备上继续工作。**

目前的主要负担来自三个方向：辅助功能重复解释“工作状态”；同一个动作保留多条入口和旧实现；远控、传输、工具维护、发布体系同时扩展，验证工作长期没有收口。应当先减少操作分支和失真的统计，再整理实现，最后决定哪些高级能力继续投入。

不建议推倒现有 Agent/账号/设备模型，也不建议为了变小而删除公司账号、自定义路径、会话容灾或安全保护。个人同时有几个订阅账号和一个公司 API 账号，是核心场景。

本次已完整阅读 3,198 行 Mesh 权威方案，核对产品、功能审计、内部结构、路线及庭院文档，并检查启动、账号创建、身份关联、会话/活动、额度、设备、传输、庭院、工具、持久化和发布检查的关键实现。对遗留入口做了全 `src` 引用搜索，对统计和拖放做了隔离复现。**这是一轮产品与架构评估，不是逐行安全审计；没有使用次数统计，也没有做全量性能压测或重新验证物理双机。**“建议删除”是价值判断；“已复现问题”另列证据。

## 2. 项目现在实际由什么组成

| 层次 | 当前作用 | 评价 |
|---|---|---|
| 本地账号与启动 | Profile 独立目录、官方客户端发现、多开、精确唤起、Windows/macOS 路径适配 | 核心，优先保证可靠 |
| Agent 目录 | Agent、实际登录绑定、设备部署、具体运行位置；多端去重和显式归属 | 必要模型，普通操作应少暴露内部术语 |
| 会话读取 | 多客户端只读扫描、逻辑会话去重、搜索、定位、复制、Markdown 导出 | 核心，统一统计的事实来源 |
| 就绪准备 | 为选定 Agent 创建独立环境，等待安装/登录，验证并提交 | 保留；后台不得弹客户端的现有修复很重要 |
| 状态与额度 | 进程/会话活动、Codex 官方额度、卡片/庭院展示 | 保留可验证信号，删除伪任务指标 |
| 庭院 | 同一 Agent 数据的另一种呈现、外观、场景、拖放、排行、陪伴账本 | 保留特色呈现，削减附带业务动作 |
| 个人设备网 | 身份、配对、目录事件、库存、远端打开、离线快照 | 符合长期定位，继续按需连接 |
| 交付与远控 | SessionPointer、文件、TaskPackage、屏幕、输入、四路控制台 | 用途各异；范围大，需要控制扩展和补齐验收 |
| 工具与发布 | 14 条工具记录、多种安装源维护、自更新、两端签名和成品验证 | 安装发现必要；通用工具维护可以收缩，发布安全不能省略 |

当前没有内嵌聊天、自动任务执行和工作流编排。`origin/develop` 的六个独有提交才包含工作图、调度器和 watchdog；相对分叉点增加 9,155 行、删除 13 行。这一组功能没有进入当前 `main`，不应作为“本次删掉的已有功能”统计。

代码体量按 Git 已跟踪的文本文件计数，包含空行、注释、词表；不是有效代码量，也不是可删除量：

| 范围 | 行数 |
|---|---:|
| `src` 的 JS/CSS/HTML | 60,106 |
| `src/renderer.js` | 9,161 |
| `src/main.js` | 4,491 |
| `src/mesh` + `src/remote` | 19,373 |
| 三份主窗口样式：styles / workspace / yard | 8,677 |
| `src/yard` | 3,017 |
| `src/task-package` | 2,160 |

Mesh/远控目录约占 `src` 的 32%，且尚未计入 Main、Renderer 中对应逻辑。整个庭院目录只有约 5%。因此仅删除猫的形象不会解决主要维护问题。HTML 声明了 24 个 Dialog；部分承担不同事务，数量本身不足以证明它们重复。

## 3. 建议删除或退休的功能

| 项目 | 建议 | 理由与替代 | 优先级 |
|---|---|---|---|
| 工作量分数、排行榜、第一名皇冠 | 删除 | 会话文件/活跃数量不能代表工作成果，也不能可靠跨账号比较。选择账号用最近活动、就绪状态和可信额度即可 | 高 |
| “今日完成数”与全局陪伴时长账本 | 建议退休 | 静默十分钟被记为收工，两个运行位置会累计两份时长；容易被理解为任务完成数和人的工作时长。若保留娱乐价值，应明确为本机活动估算，移出主工作流 | 高 |
| 庭院工作亭/池塘的业务拖放 | 删除这两个快捷操作，保留拖动摆放和点击选择 | 与打开账号、会话详情重复，已经落后于主流程并有实际异常；减少第二条动作路由 | 高 |
| 旧配对表单与失效事件绑定 | 清理 | 当前设备向导已经接替，残留代码不会增加能力 | 高 |
| 永久隐藏的旧账号详情 DOM 与写入 | 清理 | 当前界面已有 Agent 管理和运行位置详情，隐藏容器仍在参与渲染 | 中 |
| 一键更新所有第三方工具 | 建议移除批量入口 | 对核心账号管理帮助有限；不同安装来源更新的排查成本较高。保留所用客户端的发现、版本和单项明确更新 | 中 |

排行、账本和庭院拖放原属已批准 UI 行为。所有者随后批准本报告的删减，已同步权威方案和对应测试；窗口仍保持 Header、Footer、三个固定面板和四个全局入口。

## 4. 已确认的代码证据

### A. 会话列表与活跃统计使用了不同口径

[会话分类器](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/mesh/domain/session-identity.js#L24) 已排除 internal-child；[活动扫描](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/activity.js#L57) 则按扫描文件计数。Codex 注册项没有提供会话根去重的 `sessionKeyOf` 或 `sessionCounts`，组内 [mergeActivity](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/identity-groups.js#L95) 继续相加。

临时目录构造 1 条根会话、2 条指向它的内部子记录，直接调用当前源码，结果如下：

| 输出 | 结果 |
|---|---:|
| 默认会话列表 | 1 条 |
| activity.activeToday | 3 |
| activity.activeNow | 3 |
| 同一份 activity 被两个同源槽位聚合 | 6 |

这会影响排行，也会影响“并行活跃”信息。删除排行只能减少一个错误出口；仍需让活动计数复用逻辑根身份，并按真实数据根/副本去重。不要为修复统计而让每次轻量轮询完整解析所有 transcript。

### B. 账本计算的是运行位置累计时长和静默事件

[companion.tick](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/yard/companion.js#L38) 对每个 working ID 累加时长，静默超过 GRACE 后 completed 加一；[Renderer](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/renderer.js#L6082) 传入的是 Profile ID。

隔离输入两个槽位同时工作一分钟，得到 2 分钟；之后静默超过十分钟，completed 得到 2。过程中没有任何任务完成证据。

活跃轮询在前台每八秒执行；账本每轮提交设置补丁。Main 已有内容相同不落盘的检查，所以空闲时并非每轮写盘；持续工作时账本会变化，可能触发约 450 次/小时设置写入及备份。这是调用路径推导，不是实测磁盘负载。

### C. 庭院业务拖放存在失效调用

[executeYardIntent](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/renderer.js#L5943) 在找到会话后调用 `setActiveSession(profileSession)`。全 `src` 搜索只有这一处引用，没有定义；现有会话入口已经改用 `focusSession` 和独立 UI Context。

用 Node VM 执行原函数，并替换选择/读取依赖为无副作用桩，得到：`ReferenceError: setActiveSession is not defined`。复现条件是业务拖放后解析到已有会话。它不能被描述成整套庭院都不可用；普通点击和摆放是不同路径。

若暂时保留业务拖放，必须先接回统一的会话聚焦/动作路由并验收；若同意精简，删除业务区域及对应处理比维护第二套导航更直接。

### D. 旧 UI 已经退出产品，但代码仍在

- [Renderer DOM 表](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/renderer.js#L197)：`globalMoreMenu` 没有对应 HTML，也没有 `els` 使用。
- 同一表中的 `meshJoinPanel`、`cancelJoinMeshBtn`、`confirmJoinMeshBtn` 没有对应 HTML；[事件绑定](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/renderer.js#L1542) 仍在。
- [createDeviceInvitation](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/renderer.js#L5040) 在 `src` JS/HTML 中只有定义；现有入口使用设备任务向导。
- [account-legacy](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/index.html#L103) 被父容器永久隐藏，而 [renderAccountHeader](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/renderer.js#L7073) 继续更新其字段。
- `appColor` 在 `src` JS/HTML 中也只剩定义，可与上述内容一起核对后清理。

没有 Renderer 直接调用的 Preload 方法不自动等于无用：还可能服务调试、恢复和其他受控调用。这轮不把它们整批列为可删接口。

### E. CSS 是“降优先级”，尚未完成退休

[styles.css](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/styles.css#L1) 有 4,556 行，包含 v2、v3 和后续布局覆盖；[workspace.css](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/workspace.css#L1) 又定义当前布局和组件，旧庭院样式还有 1,104 行。三者都被主 HTML 加载。

应逐组件确定唯一规则来源，迁移仍在使用的旧规则后删除覆盖链。**不能直接删除 styles.css 或根据一次 CSS coverage 清空未命中规则**：隐藏弹窗、另一主题、其他语言和错误状态仍可能依赖它们。

### F. 文档检查强化了重复和陈旧信息

[check-docs.js](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/scripts/check-docs.js#L31) 把 527/526、21/21 等结果写成常量，并要求七份文档分别出现这些数字和同一份物理库存证据。本次基线上一轮实际全量测试已经是 549 项、548 通过、1 跳过，文档检查仍认可旧数字。

建议把结果统一放在带提交号、时间和环境的证据记录中；产品/场景/路线只链接记录。保留发布边界和链接检查，删除“多份文档必须复制某个历史数字”的检查。历史证据可以保留，但必须标为历史，不能继续称为当前总数。

## 5. 应当合并简化的地方

### 账号创建：统一普通流程，保留关系修复

当前既有首次使用/首次准备，也有普通新 Agent、新运行位置、已有登录归属、合并和拆分。对象不同，并非都能删除，但普通用户不应先回答内部数据库关系问题。

建议正常入口统一为“添加 Agent”：选择客户端、选择已有环境或新建独立环境、命名、检查后打开。为已有 Agent 增加另一个账号或运行位置，留在“管理 Agent”中；合并/拆分只服务明确的关联和纠错，不放在首次上手必经路径。不要把多个个人登录或个人/公司账号默认合为一只 Agent。

现有 Profile、AccountBinding、Deployment 不合并成一张表；它们分别负责文件位置、登录身份和设备就绪，删除任何一层都可能重新引入串号问题。旧本地 IdentityGroups 仍用于未初始化 Mesh 和迁移，也不能整体删除。

### 公司接口：建立环境交接，不复制 AgentDock 的产品

结合本次已处理的公司账号案例，建议职责明确为：

| 组件 | 负责什么 |
|---|---|
| AgentDesk | 管理独立账号环境、明确配置目录、启动目标和安全的配置状态诊断 |
| AgentDock | 在其支持的目标环境内维护公司 provider、接口地址、模型和认证材料 |
| 官方客户端 | 使用该环境执行实际请求，管理其会话 |

第一步应是“登记/选择已经配置好的独立环境”，让 AgentDesk 能告诉配置工具确切目标目录；需要 AgentDock 支持自定义目录时，提供可核对的路径和能力契约。一个环境的配置只有一个明确写入者，不能两个管理器各改一半。

现有 [配置所有权测试](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/test/codex-config-ownership.test.js#L8) 明确不让 AgentDesk 接管 Codex config。上一次在本机建立“公司 API”账号是一次配置操作，**不等于仓库已有通用的公司接口账号向导**。如果以后要求在 AgentDesk 内直接输入接口和密钥，应单独批准一个限于目标 Profile 的配置适配器，修改该边界；不用新增全局代理、自动路由或云端密钥库。

OAuth 账号和 API key 环境还需分别表达身份可信度。当前 [Codex 身份读取](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/identity.js#L64) 只取 `tokens.account_id`，API key 环境不会自然得到同样的稳定身份；不能拿接口域名、账号名字或密钥内容推定同一个人。公司额度未知也不能显示为个人订阅剩余额度。

### 工具维护：缩为当前使用的工具

固定目录有 4 个桌面工具、9 个 CLI 和系统终端，其中多种 CLI 没有相应的会话扫描或首次准备适配器。建议默认只显示当前已登记/已安装相关工具，其余保留在明确的支持清单；暂停增加更多包管理器和批量维护能力。

保留 `apps`、CLI discovery 和安装路径适配，它们还服务准确启动、诊断和 Codex 额度。工具目录与客户端注册表用途不同，可共享品牌、下载入口和能力元数据，不能因为都是“目录”就硬合并全部逻辑。

### 额度与活动：一个事实，多处一致展示

保留当前账号额度和全部账号比较；用同一个详情组件切换范围，顶部摘要与卡片共用同一份可信度判断。不再同时维护排行分数、猫能量、陪伴账本等多套“谁更能工作”的解释。

保留进程运行、近期会话活动、官方额度三类原始语义，未知就显示未知。额度按实际登录去重，活动按逻辑会话和来源去重，二者不能相加成通用分数。

## 6. 暂停扩展，而非直接删除

| 能力 | 建议 | 继续推进的条件 |
|---|---|---|
| 四路远控网格和资源调度 | 保留已有代码，近期优先单设备可靠查看/控制，暂停增加模式和容量 | 单设备断线释放、权限、显示器和跨平台基本路径有物理证据后再验证多路 |
| TaskPackage 的更多原生适配器、跨 Mesh 直连 | 保留当前便携包和已有直送代码，暂停扩张 | 先完成当前 Codex 导入及真实直送/拒绝/撤权/断线恢复 |
| Blueprint 的技能/工具/项目自动恢复 | 暂停 | 当前适配器的非空 requirements 会被拒绝，不能宣传为已经自动恢复技能与工具 |
| 旧端目录兼容 | 暂留，制定明确退役条件 | 已配对设备版本盘点、升级窗口、备份和兼容验证齐备后才能删除旧网络协议路径 |
| `origin/develop` 工作流编排 | 不合入 main，保留历史分支 | 若确有自动执行产品目标，另立范围和架构决策，不与本轮精简混合 |
| 无人值守、GPU 自动分发、云端邮箱 | 继续不做 | 另行形成明确需求和批准范围 |

Blueprint 当前仅声明 Claude/Codex 桌面准备适配器，`portableSettingKeys` 为空，非空技能/工具/项目要求均返回 unsupported，见 [provisioning-adapters.js](https://github.com/shuqianglin1997/agent-desk/blob/3a4919a14c05e4db1c828cccad3ec9e024023efe/src/mesh/main/provisioning-adapters.js#L1)。先修正文档的能力承诺，不应为了“填满模型”扩展功能。

SessionPointer、普通文件、Markdown 导出与 TaskPackage 用途不同：分别传坐标、传选中文件、导出可读正文、交付固定工作快照。它们可共享传输与接收展示组件，但不能合成一个语义不明的“同步”按钮。保留独立权限和不可变包格式；安全校验、来源保留与防重放账本不是冗余。

同样，不删多平台路径、Profile 进程归属、Crashpad 熔断、密钥保护、目录 tombstone、schema 迁移备份或本机会话降级。当前普通启动已经避免自动联网/拉起客户端的路径应保持，不再为同一目的新增一套“简洁模式”状态。

## 7. 实施顺序与验收

以下是建议批次，工作量以现有架构为基础粗估；不包含等待真实设备、签名证书或网络环境的时间。

| 批次 | 改动范围 | 验收结果 | 粗估 |
|---|---|---|---|
| A：正确性与遗留清理 | 修复或删除庭院失效动作；清旧配对/隐藏 DOM；统一根会话统计和同源去重 | 1 根 + N 内部记录只计 1；同源多槽位不翻倍；拖放不再异常；个人/公司 Profile 路由不变 | 2–4 个工作日 |
| B：产品入口精简 | 经确认移除排行、完成账本和业务拖放；普通新增流程收敛；批量工具更新退出主流程 | 单人多个个人账号与公司账号可清楚创建/选择；主窗口骨架和复制契约不变；低频关系修复仍可达 | 3–5 个工作日 |
| C：实现与文档减重 | 按功能拆 Renderer/Main；逐组件迁移 legacy CSS；统一证据记录和文档链接 | 同一组件只保留一套布局规则；三语/双主题/隐藏/错误态不回归；文档结果绑定提交 | 4–7 个工作日 |
| D：高级能力收口 | 不加新功能，完成单设备远控、既有传输与 TaskPackage 的真实验收 | 双机、Windows/macOS、断网/睡眠、授权撤销和导入恢复逐项记录 | 取决于设备与网络条件，暂不承诺日历工期 |

批次 C 应按功能域拆分，例如账号与准备、会话浏览、设备向导、传输、额度/活动、工具设置。先移动完整职责并保持行为，再合并重复逻辑；不引入新前端框架，不用拆出大量小文件制造新的复杂度。Main 保留生命周期与装配，IPC 按领域注册；始终保留精确 sender 校验和本机 ID 重查。

CSS 必须分批退役。无动态场景覆盖的样式只列候选，不能自动删除。旧配置字段如 `isProtected` 和 `welcomed` 则先明确新语义、保留读取迁移，再停止新增写入；旧数据可读性与旧 UI 入口是两件事。

验收至少覆盖：

1. 多个个人账号与公司环境共存、分别启动和切换，目录/认证/会话不串用；自定义目录与 Windows 非默认安装不退化。
2. 根会话、子记录、归档、同源多槽位、远端副本和未知活动分别有正确计数；不以标题或时间模糊合并。
3. 选择 Agent/设备/运行位置不意外清空会话选择；复制仍只有路径和坐标。
4. 三面板、四个全局弹窗、三语、明暗主题、卡片/庭院、错误/空状态和键盘导航通过实际窗口路径。
5. 删除最后一个 Agent/位置后重启不复活；Mesh 不可用仍可读取本机会话；暂停高级功能不破坏旧数据和正在进行的事务。
6. 性能记录统一统计扫描次数、扫描耗时和设置落盘次数。先取得基线再定阈值，不把本报告的行数或推导值当作性能提升结果。

测试随职责迁移，优先验证行为；不只改源码正则让测试重新变绿。已有安全与持久化负向用例继续保留。源码、UI、成品、物理设备和发布门禁分别记账；产品范围缩小也不能把尚未通过的 Preview 宣称为稳定版。

## 8. 本轮实施结果与后续边界

- A 已完成：列表/活动共用 Codex 根身份和归档规则，排除内部子记录；同设备同源多 Slot 只扫描和累计一次；Cursor 按数据库用户会话统计。旧配对绑定、隐藏账号 DOM 和失效拖放导航已清理。
- B 已完成本批收敛：删除排行/皇冠、推断完成/陪伴账本、提醒总开关和业务拖放；庭院保留点击与摆放。普通新增选名称/客户端并在本机准备独立环境；既有个人/公司接口环境仍走管理中的导入，未新增密钥编辑器。工具默认已安装项、其余折叠，取消批量更新并保留单项操作。
- C 完成本批职责迁移：工具展示与本机读取 IPC 拆分；卡片、庭院、当前与全院额度复用可信度判定；移除退休组件的样式，将上下文菜单剩余规则归入 canonical 层。其余 Renderer/Main 大功能域和 legacy CSS 的逐组件迁移继续保留为后续批次。
- C 文档收敛已完成：当前结果统一引用 [VALIDATION.md](VALIDATION.md)，机器记录包含 Git 基线、未提交源码摘要、时间、环境与检查范围；历史证据保留来源，不再硬编码为当前测试总数。
- 性能只记录一组隔离合成样本：四个同源槽位从四次扫描降为一次；首次身份读取更慢、缓存轮询更快，详见 [测量记录](validation/activity-benchmark.json)。没有声称所有机器都加速，也未实测设置磁盘写入吞吐。
- D 只落实暂停扩张与开放门禁清单；未完成物理双机、公网、Windows、签名成品或发布验收。自动化详情与限制见验证记录。
- 所有代码修改保留在本地工作树，未推送、未合入 develop、未安装覆盖当前应用，也未改个人/公司账号配置。历史账本与提醒设置仍可读取，停止新写入，不清理用户旧数据。
