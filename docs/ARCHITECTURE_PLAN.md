> 状态：草案，待所有者审阅。批准前不改产品代码。
>
> 评估对象：提交 `24fdb32`（2026-11-24）的代码，并假设“猫有多忙、新回复、颜色标签”已按 `docs/SESSION_MARKS_PLAN.md` 做完。
>
> 本文不覆盖 `docs/PERSONAL_AGENT_MESH_PLAN.md`。整理期间界面、行为和安全边界都不变；产品模型以那份基准为准。

## 1. 结论

没有到要推倒重来的程度，但有四个结构性问题，其中一部分已经在让界面显示错的东西。

骨架里做对的，整理时不动：

- 主进程 104 个模块之间没有循环依赖，也没有完全没人用的文件。
- Mesh 的 domain / protocol / storage / main 分层、调度中枢的 adapters / roster / store / runner 拆分是清楚的。
- `json-store.js` 的原子写入被七处共用；116 个通信接口在主进程、preload、界面三处一一对应，没有悬空的。
- 三份词表各 1697 条，完全一致。
- 额度请求有防重复和有效期；会话文件只读头尾；每个同步子进程都有超时；卡片原地更新；窗口隐藏时猫的动画会停。

四个问题：

| | 问题 | 最直接的后果 |
|---|---|---|
| A | 两个文件什么都管：`renderer.js` 9681 行、`main.js` 5184 行，各有一个约 900–1300 行的函数 | 改任何东西都要进这两个文件，几个会话同时开发必然互相碰 |
| B | 同一个事实或操作有好几份实现，而且已经不一致 | 界面、命令行、调度中枢对同一条会话可能选中不同的文件；同一张卡片上数字和猫的状态互相矛盾 |
| C | 刷新靠“同步、全量、重扫”，界面靠“整表重建”，读失败被当成“没有” | 账号和会话一多就卡；数据会显示成别的账号的、过期的或凭空清空的 |
| D | 三代样式叠在一起；三分之一的测试在比对源码文字 | 改样式经常不生效；一动结构测试就成片失败，测试反而成了阻力 |

## 3. 具体问题

### 3.1 已经在显示错的（先修）

1. **快速切换账号，列表可能是上一个账号的。** `loadSessions` 没有“只认最新一次”的检查，谁最后返回用谁的（`renderer.js:3300-3371`）。
2. **命令行账号和 macOS 默认位置的账号永远不显示“干活”。** 认不出是否在运行时返回的是“没开”而不是“不知道”（`process.js:25-63`、`yard/cats.js:55-62`）。
3. **卡片在更新，列表不更新。** 卡片 8 秒一次，列表只在窗口重新获得焦点时刷新。
4. **读失败等于没有。** 活动读失败，所有猫变空闲；某个账号扫描失败，它的列表变空；扫描失败还会被当成空清单发给已配对的设备（`mesh-service.js:1494`）。
5. **会话数三处三种数法**，Claude 命令行的旁支记录一处算、一处不算；目录遍历超过 12000 项会不声不响地截断。
6. **`profiles.json` 有被写成空的风险。** 主文件在、但所有候选副本同时读失败时会这样（`profile-store-policy.js:15-22`）。
7. **DSH 账号的绑定选择框里永远没有可选项。** 同一个名字规整函数写了两份，一份把 `dsh-cli` 变成 `dsh`，另一份不变（`mesh/domain/agent-catalog.js:4`、`renderer.js:2205`）。
8. **“立即刷新额度”在已有请求进行时不起作用**（`renderer.js:3486`、`quota-service.js:131`）。
9. **名字以 `..` 开头的文件夹会被当成越界。** 这个宽松写法在四处，其中有安全边界在用。

另有两条小的：Codex 首行超过 64KB 时标题和目录丢失；读首行出错时文件句柄不关。

### 3.3 旧一代还留着

- **旧的 Codex 导入**：按钮已经不在页面里，但对话框、23 条文案、5 个通信接口和一套自己的目录识别都还在。
- **庭院**：`sprites.js` 里的旧猫只剩开机时的影子在用；设置里六个字段还在被规整和保存，但没有任何地方读。
- **样式三代**：34 个颜色变量在三张表里各定义一次，只有最新一张生效；旧表里的 `!important` 反过来压住新皮肤（额度文字因此是 11.5px 而不是规定的 12px）。
- **一个东西七个名字**：代码里 Profile、slot、account、Agent、cat、location、runtime 混用，界面英文在同一组文案里也混着用。

### 3.4 慢在哪

按 10 个账号、每个 500 条会话估算（待第 0 阶段实测校正）：

- 会话扫描没有缓存。一次“全部”刷新约读 1.6 GB，全部在主线程同步进行。
- 只为了拿几个数字，就把所有账号完整扫一遍；启动时这样的完整扫描连做三到四次。
- 每 8 秒一次同步的进程查询，每个受管账号另外每 2 秒一次，窗口隐藏时也不停。
- 每敲一个字、每点一行、每来一个调度事件，整张会话表重建一遍。

## 4. 从 Blender 和 Godot 学什么

两份源码都实际读过，读了哪些文件、哪些没读到，记在 `4-blender.md` 和 `5-godot.md` 里。没读到的主要是：Blender 的两页开发手册、“求值时复制”的实现；Godot 的旧文档路径和一部分函数体。下表只采用读到了的部分。

| 机制 | 在它们源码里 | 用到 AgentDesk 上 |
|---|---|---|
| 单向分层 | Blender `source/blender/` 下各模块只能往下依赖；Godot 的 core → servers → scene → editor，以及 `main/main.cpp` 里明确的启动顺序 | 定五层，下层不认识上层，用一个检查脚本看住（5.1） |
| 数据只定义一次 | Blender 的 DNA（数据布局）与 RNA（每个属性描述一次，界面、脚本、命令行共用）；Godot 的 ClassDB 与 `GLOBAL_DEF` 设置 | 每个存盘文件、每项设置、每个客户端各有唯一的一处定义（5.2、5.3） |
| 版本迁移阶梯 | Blender `blenloader` 里按版本号逐级迁移的函数（如 `blo_do_versions_400`） | 所有存盘文件统一带版本号，迁移集中在一处按序执行 |
| 操作只有一个入口 | Blender 的 `wmOperatorType`：先 `poll` 问能不能做，再 `exec` 做；菜单、快捷键、脚本走同一张注册表 | 命令层：界面、命令行、调度中枢调用同一份命令（5.5） |
| 变了才重算、才重画 | Blender 的通知（`wm_event_system.cc`，会合并）与依赖图“先标记、只重算标记到的”；Godot 的信号与延迟调用队列 | 会话索引按文件标记脏、只重读变了的；变化按主题合并后通知界面（5.4、5.6） |
| 重活放到别处，用句柄联系 | Godot 的服务端在命令队列后面运行（`CommandQueueMT`），场景只拿带代数检查的句柄（`rid_owner.h`） | 扫描放进工作线程；每次请求带代数，过期的结果直接丢掉（5.4） |
| 资源有主、有缓存 | Godot 的引用计数资源与按路径的缓存；Blender 数据块的所有权与使用计数 | 解析过的文件按“路径、大小、修改时间”缓存；定时器和子进程都登记归属（5.9） |
| 功能自己登记 | Godot 各模块的 `register_types`，按层级初始化 | 客户端、命令、存盘文件、定时任务都向注册表登记，`main.js` 只负责按顺序启动 |
| 错误有统一通道 | Blender 的 Reports | 统一的结果类型和固定的原因码，失败不再伪装成空（5.2） |

明确不照搬的：自动生成数据结构表、完整的依赖图、手工引用计数、可挂起的交互式操作、引入框架或打包器。这个应用用不上，只会变重。

## 5. 目标架构

### 5.1 五层，单向依赖

```
ui         界面：视图、对话框、动效、声音          只通过 bridge 说话
bridge     preload 与通信接口：一张表定义全部入口
commands   命令：每个用户可见的操作一条，带“能不能做”和“做”
services   领域服务：会话索引、活动、额度、调度中枢、Mesh、任务包、账号登记
clients    客户端适配器：每家客户端的全部知识
core       纯函数与基础件：路径、标识、时间窗、结果与事实类型、存盘、调度器
```

- 只能向下依赖。`core` 不碰 Electron；`clients` 不认识 `services`；`ui` 不直接认识 `services`。
- 一个检查脚本读依赖关系并在测试里执行，违规即失败。先只报告，逐阶段收紧。

### 5.2 数据：一个事实只有一个来源

- **事实带可信度。** 凡是显示给人看的推断，都用同一种形状：值、可信度（确切 / 推断 / 不知道）、取得时间、来源。“不知道”必须显示成不知道，不能落成“否”或 0。
- **结果不等于空。** 读取返回“成功加值”或“失败加原因码”。失败时界面保留上一次的好数据并标注，Mesh 不发布失败的扫描。
- **标识只有一套。** 会话用 `SessionTable.keyOf` 的键，运行位置用 `deviceId + profileId`，与基准 7.9 一致。按标识找回会话只有会话索引的一个函数。
- **存盘统一。** 所有 JSON 文件走 `json-store`：带 `version`、默认值、校验和按序迁移。`profiles.json` 只有一个读取入口。退休字段在一次迁移里删除。
- **时间窗只定义一次。** “在跑”“活跃”“额度新鲜”各一个常量，放在 `core`。
- **用词表。** 代码里只用 `agent`（全局的那只猫）、`profile`（本机的一个运行位置）、`binding`、`device`、`conversation`、`replica`。界面用词见第 9 节待定事项。

### 5.3 客户端适配器

每家客户端一个目录，声明并实现它的全部知识：名称与可执行文件、数据目录与识别标记、身份文件在哪、会话记录怎么扫与怎么解析、能不能判断“在运行”和“最后一句是谁”、额度怎么查、密钥怎么交接、调度中枢怎么调用、猫的默认毛色。

- 其他代码只问适配器“你会不会、结果是什么”，不再写 `appId === 'codex'`。
- 每种记录格式只有一个解析器，导出、调度结果、附件、额度都用它。
- 新增一个客户端等于新增一个目录，有清单可对。

### 5.4 会话索引

一个服务负责“磁盘上有哪些会话、各是什么状态”，其余部分都从它取：

- 按文件的“路径、大小、修改时间”缓存解析结果，只重读变了的文件。
- 在工作线程里扫描，主线程不被阻塞。
- 列表、会话数、在跑的条数、最后一句是谁、按标识找回，全部出自同一份记录，所以不会再互相矛盾。
- 每次查询带代数，过期的结果丢掉。
- 截断、读失败都作为状态带出来。
- 进程查询改为异步，同一时刻全应用共用一份快照。

### 5.5 命令层

每个用户可见的操作是一条命令：标识、输入的形状、`poll`（现在能不能做，不能时给固定原因码）、`exec`。

- 通信接口、命令行、调度中枢都是这张表的薄壳，不再各写一遍。
- `registerIpc` 按功能拆进各自的模块；preload 暴露的入口由同一张表决定，仍是明确的白名单。
- `docs/INTERNAL.md` 的接口清单由脚本从这张表生成，不再手写。
- `main.js` 只剩按顺序启动。

### 5.6 刷新模型

- 一个调度器管所有周期任务：登记间隔和“窗口隐藏时是否暂停”，统一退避和停止。
- 主进程在数据真的变了时，按主题发出合并过的通知；界面按视图订阅，只更新受影响的部分。
- 列表与卡片用同一个变化来源，不会一个新一个旧。
- 启动时先画出账号，再补会话和额度；全程只做一次扫描。

### 5.7 界面层

- 一个状态仓库（由现有的 `ui-context.js` 扩展），所有选择和数据都在里面，可订阅、可在测试里整体重置。
- `renderer.js` 按视图拆开：名册、会话表、详情、各对话框、公共部件。每个视图只绑定自己根节点上的事件。
- 会话表按行的标识做增量更新，搜索加防抖。
- 对话框、菜单、浮层各只有一种做法。
- 界面脚本之间的依赖要显式写出来。用原生模块还是保留现状加命名空间，由第 0 阶段的小试验决定。

### 5.8 样式

- 只留一代：变量定义一次，然后是基础、部件、各功能。
- 旧样式表里仍在生效的规则迁走后整表删除。
- `!important` 只允许出现在一张列明原因的清单里。
- 用测试看住：跨表重复的选择器为 0，变量各只定义一次。

### 5.9 资源与生命周期

- 定时器、子进程、工作线程、音频设备、画布循环，创建时都登记归属。
- 窗口隐藏时该停的停，退出时由归属者逐个关闭，包括现在靠标准输入关闭来结束的 `codex app-server`。
- 只增不减的数据（Mesh 的事件表）定期压缩；系统钥匙串每次启动只解密一次。

### 5.10 测试

- 每动一块之前，先为它补“行为不变”的测试，再动。
- 比对源码文字的测试只保留真正的安全不变式（如内容安全策略、不开启 Node 集成），其余换成验证行为的。
- 那项不稳定的测试改为注入进程检查，不再真的调用 `lsof`。
- 一份合成数据（10 个账号 × 500 条会话）和计时脚本，作为性能的尺子。

## 6. 迭代规划

每个阶段都是行为不变的整理，一批一提交，三项检查通过，并在不显示窗口的情况下把真实界面走一遍。每个阶段结束由所有者决定是否装上实看。

| 阶段 | 做什么 | 做完的标志 |
|---|---|---|
| 0 尺子与安全网 | 指标脚本和分层检查入库（只报告）；合成数据与计时；给会话扫描、活动、命令行输出、接口返回补“行为不变”的测试；修那项不稳定的测试；界面模块方式的小试验 | 有基线数字；之后每个阶段都能对比 |
| 1 止血 | 3.1 的九条和两条小的，每条配一个行为测试 | 这些错不再出现；不改结构 |
| 2 公共底座 | 建 `core`：路径、标识、读 JSON、时间窗、结果与事实类型、存盘统一；替换 3.2 里的各份副本；删旧的 Codex 导入和庭院遗留；设置迁移掉退休字段 | 路径判断 1 份、读 `profiles.json` 1 份、原子写入 1 份；多出的接口和文案删除 |
| 3 客户端适配器 | 每家客户端一个目录；清掉分散的判断和并行的表；每种记录格式一个解析器 | 适配器之外没有按客户端名字的判断；新增客户端有清单 |
| 4 会话索引 | 缓存、工作线程、代数、统一计数与找回；活动从索引出；进程查询异步共用；启动只扫一次 | 合成数据下主线程单次阻塞达标；三处会话数一致 |
| 5 命令层与主进程 | 命令注册表；接口、命令行、调度中枢改成薄壳；拆 `registerIpc`；调度器与资源归属；Mesh 总览不再触发扫描 | `main.js` 只剩启动；接口清单由脚本生成 |
| 6 界面层 | 状态仓库；按视图拆 `renderer.js`；会话表增量更新；对话框与菜单统一；订阅变化通知 | `renderer.js` 不再存在或只剩启动；整表重建消失 |
| 7 样式 | 合成一代，删旧表 | 重复选择器 0；变量各定义一次 |
| 8 测试与文档 | 换掉比对文字的测试；重写 `docs/INTERNAL.md`；用词表；给开源贡献者的结构说明 | 文字比对只剩安全不变式；文档与代码由检查看住 |

顺序的理由：先修会显示错的；再自下而上，因为上层要等下层的接口稳定；界面放在后面，因为它依赖数据层的新接口；样式最后，因为类名会随界面拆分变动。第 8 阶段的测试替换其实贯穿全程，表里单列是为了收尾。

规模上，第 4、5、6 阶段最大，各需要拆成多批。

## 7. 整理期间的纪律

- 不加新功能。发现的缺陷记下来，属于 3.1 那一类的在第 1 阶段修，其余等对应阶段。
- 一次只有一个会话在写同一批文件。
- 每批先有行为测试，再改，再过三项检查，再提交（`AGENTS.md` 的“Commit as you go”）。
- 不动的东西：1040 × 840 的窗口骨架、“复制会话信息”的格式、Renderer 无 Node、preload 白名单、Main 对标识重新查表、密钥不经过 AgentDesk 存储。
- 每个阶段结束更新第 8 节的数字。
