00 / VERDICT

不是换皮问题，是层级系统没有建立。

当前实现把“固定三面板”误当成完成了信息架构。实际上，面板只是盒子；盒子内部仍然沿用旧控件、旧样式覆盖和旧尺寸假设，所以视觉上有大体结构，使用时却没有清楚的主次和稳定节奏。

保留 宏观页面骨架

Header、顶部 Agent、左下会话、右下详情、Footer；庭院/卡片共用业务状态。

推倒重排 面板内部层级

标题、筛选、当前对象、主操作、状态、低频管理需要重新分级和排序。

先治理 CSS 与浮层架构

先消除相互覆盖的样式代际和裁切根因，否则任何细节润色都会再次走样。

核心结论：不增加任何区域，只重新分配现有区域里的注意力。

顶部 Agent 面板负责“选谁、在哪里运行、现在能做什么”；左下负责“找会话”；右下负责“理解并操作当前会话”；Footer 只负责全局状态。设备、工具、活动、设置继续各自使用独立弹窗。

1
Header 不是同一条基线

品牌、Lens、全局入口在视觉上像三套独立组件，而不是一条全局导航。

2
图标语言混杂

⌁、◇、◎、⚙、🏆、⇄ 同时出现，线宽、语义和文字间距均不一致。

3
模式状态表达反了

“⇄经典”表达下一步动作，而不是当前模式；用户需要先推理现在在哪里。

4
场景设置压过主体

跟随/白天/黄昏/夜晚常驻四按钮，场景设置比猫和 Agent 选择更醒目。

5
当前 Agent 侧栏过载

对象标题、并行状态、三个动作、两个额度入口都使用粗边框或强色块。

6
浮层边界错误

菜单是绝对定位，但祖先面板裁切；提高 z-index 也无法逃出裁切上下文。

7
工具栏像控件拼盘

分段、搜索和显示菜单高度、边框、字体和选中方式不属于同一系统。

8
紧凑模式仍横滚

左面板的真实内宽小于表格硬最小宽度，横向滚动不是偶发，而是必然。

9
空状态没有任务说明

只写“未选择”，没有说明单击看详情、勾选做批量操作，也没有视觉锚点。

10
Footer 权重失衡

提醒是全局开关没错，但橙色木牌像主操作；左侧又出现当前 Agent 瞬时说明。

02 / GEOMETRY

先把算不通的尺寸算通。

当前外窗 1040 × 840，macOS 原生标题栏约 28px，Renderer 内容区约 1040 × 812。布局问题不是“再缩小一点字体”能解决，而是固定值之间本身矛盾。

− 10（列间距）− 340（详情）
= 666px 面板宽
666 − 26（面板 padding）≈ 640px 内容宽 但紧凑表格 min-width = 720px → 至少多出约 80px。
当前 · 顶部 Agent 高度 220 − 34（面板标题）= 186px
186 − 24（上下 padding）
− 24（三段 gap）≈ 138px
留给标题、位置、动作、额度四组内容 菜单再向下展开时，必然越过面板底边并被裁切。
裁切根因z-index 不是解法

子元素无法越过祖先的裁切边界。菜单必须进入浏览器 Top Layer，或由根级 Overlay Portal 承载。

滚动根因Compact 不能有硬最小宽

紧凑模式必须在左面板内完成列预算；只有详细模式允许明确的水平滚动。

密度根因顶部面板太矮且动作太多

不是简单加高，而是同时减少常驻控件、提升顶部面板高度、收窄右侧 Agent 控制宽度。

03 / INFORMATION HIERARCHY

每层只回答一个问题。

页面不是把功能全摆出来，而是让用户从全局上下文逐层落到当前对象。以下五层冻结后，任何按钮都必须能解释自己属于哪一层。

LEVEL 0应用外壳

我在哪个设备视角？有哪些全局中心？——Header 与 Footer。

LEVEL 1面板标题

这一块是什么？数量和视图模式是什么？——每个面板唯一标题行。

LEVEL 2主要工作对象

我正在看哪个 Agent、哪条会话？——庭院/卡片、会话表、详情正文。

LEVEL 3上下文动作

对当前对象最常做什么？——打开账号、复制会话信息；每区只允许一个填充主按钮。

LEVEL 4临时浮层

低频设置或复杂管理去哪里？——Popover / Dialog / 独立全局弹窗，不改变底层工作台。

规则 01一块区域，一个主任务

当前 Agent 的主任务是打开账号；会话详情的主任务是复制会话信息。其他动作降级。

规则 02状态不伪装成按钮

“3 并行”“稳定”“在线”属于信息标签，不使用按钮边框、阴影或高饱和底色。

规则 03模式显示当前值

直接显示“庭院 / 卡片”两段，不再用“⇄经典”让用户猜当前状态。

规则 04短命令才用 Popover

最多五项、无表单、无危险确认。七项管理菜单不符合，必须进入对象管理 Dialog。

规则 05皮肤不改变语义

庭院和卡片只改变 Agent 呈现，不改变按钮、表格、详情和弹窗的控件体系。

规则 06空状态也是任务说明

明确告诉用户：单击查看详情，勾选建立批量集合；不能只留下“未选择”。

移走的内容到底放哪里

跟随 / 白天 / 黄昏 / 夜晚 + 天气→庭院画面右上只留一个“场景 · 跟随 / 晴”按钮，打开 Top Layer 小浮层。
路径 / 诊断 / 重扫 / 位置→“管理 Agent”对象弹窗中的“当前运行位置”分区，不再用会被裁切的七项菜单。
编辑 / Agent 关系 / 移除→同一对象弹窗的“全局 Agent”分区；危险动作放最底部并先做影响预览。
本号 / 全院两个大额度胶囊→当前 Agent 控制区只留一条紧凑额度摘要；点击本号或“查看全院”进入右下额度详情。
显示 · 精简 / 详细→会话工具栏保留一个“显示”Popover，当前模式以勾选显示，不再做双重文字按钮。
当前选择提示→归当前 Agent 标题区或会话详情；Footer 只显示 Mesh 同步、账本与提醒总开关。
设备 / 工具 / 活动 / 设置→维持四个独立有界弹窗；不进右下详情，也不塞入“更多”。

05 / AREA-BY-AREA SPEC

逐区排版与内容顺序。

下面不是“有哪些按钮”的排列组合，而是每一区域先回答什么、后回答什么，以及任何被移走的内容最终落在哪里。

Header全局上下文 · 58px

  • 左：品牌，固定约 210px；不重复当前 Agent、在线长句或模式信息。
  • 中：Device Lens，组件内明确显示“设备视角 / 全部设备”，不是一只裸 Select。
  • 右：设备、工具、活动、设置四个直接入口；统一 16px 图标、32px 点击高度和同一文字基线。
  • 设备徽章只表示在线数；活动徽章只表示待处理数。没有数据时隐藏，不显示 0。
  • 远控后台安全提示出现在四入口之前，颜色只用于风险状态，不与普通导航同色。

Agent 面板选择 Agent + 明确 Slot · 244px

  • 标题行：左“Agent + 数量”；右“排行”与“庭院 / 卡片”直接分段，始终显示当前模式。
  • 左舞台：庭院或卡片只负责选择 Agent；两种视图共用同一选中、状态和数据。
  • 庭院场景：时间和天气合成一个“场景 · 跟随 / 晴”按钮，Popover 内再展开，不常驻四段按钮。
  • 右控制区顺序：当前 Agent → 轻量状态 → 运行位置 → 主/次动作 → 一条额度摘要。
  • 动作：“打开账号”为唯一填充主按钮；“新增运行位置”明确对象；“管理 Agent”打开对象 Dialog，不再展开七项菜单。
  • 长名称：最多两行；状态标签自动换行但不挤压运行位置和主操作。

会话面板查找与选择会话 · 约 690 × 442px

  • 工具栏：标题/数量在左；Agent 范围、搜索、显示在右，所有控件统一 30–32px。
  • 紧凑列：选择 36、标题弹性、活跃 72、项目约 145、来源 64、位置 88；全部设备视角才显示位置。
  • Compact：禁止横向滚动；长路径和标题省略并提供 tooltip。Detail 模式才允许水平滚动。
  • 表格边界：去掉粗木框、双重圆角和内阴影；面板是唯一外框，表头 sticky、行只用 1px 分隔。
  • 选择语义：单击行只聚焦，左侧蓝线；复选框才进入批量，勾选背景使用浅蓝。两种状态不能共用同一种底色。

详情面板理解并操作当前对象 · 316px

  • 空状态：标题行仍是“会话详情”；正文在约 40% 高度居中，说明“单击查看 / 勾选批量”。
  • 已聚焦：会话标题最多两行；正文先 Agent、运行位置、项目、活跃，再折叠技术信息。
  • 多副本：来源选择是正文顶部的紧凑警示区，不把整个详情变成另一张卡片墙。
  • 动作坞：固定底部；复制会话信息是唯一填充主按钮，发送紧邻；打开与导出在次级行。
  • 批量：同一动作坞原位切换为数量、取消、复制、发送；不在会话表上方新增区域。
  • 额度 / Remote：仍然是右下详情的另外两种当前对象 Surface，不影响其余三块。

Footer全局状态 · 38px

  • 左：Mesh/本机同步状态、设备在线摘要或全局错误；不得写“已选择 peter”。
  • 右：今日收工次数、陪伴分钟、提醒总开关；保持一行且全部属于全局状态。
  • 提醒开关使用安静的有/无状态样式，不再使用橙色木牌和 2px 黑边伪装成页面主操作。
  • 瞬时成功提示可以短暂替换左侧全局状态，2–3 秒后恢复；不改变布局宽度。
06 / OVERLAYS & DIALOGS

弹窗独立，浮层也必须有边界。

当前问题不是弹窗太多，而是没有区分 Select、Popover、Dialog 和全局中心。1.14 进一步统一全局弹窗内部：Header、全局命令与事务 Footer 固定，只有命名 Content 滚动；父子流程关闭后返回原弹窗。

08 / STATE MATRIX

不是静态一张图，要把所有状态一起设计。

当前 UI 容易在真实数据下破版，是因为只验证了“有几个短名字的默认状态”。实施前需要把下面这些状态作为同一套布局的硬验收。

状态顶部 Agent会话 / 详情验收重点
初次加载恢复 Lens 的 Agent 记忆；没有则不自动选第一只。详情空状态，不自动聚焦/勾选。没有隐式选择副作用。
庭院 / 卡片只替换左舞台，右控制区完全不动。搜索、聚焦、勾选保持。控件皮肤和几何不改变。
超长 Agent 名称最多两行；状态折行但不挤掉动作。Agent 列省略并有 tooltip。中/英/日均不溢出。
单击会话不变。蓝色 focus 线；详情与单条动作坞出现。复选框仍未勾选。
勾选 1 / N 条不变。动作坞原位切批量；focused 专属动作隐藏。页面不新增选择条。
多副本未解决运行位置不替会话猜副本。详情顶部选择来源；复制/发送/打开禁用。同一修复入口，不随机选择。
设备离线Presence 标离线快照；副作用禁用。缓存会话仍可复制。时间与数据新鲜度可见。
Popover / Dialog 开启底层状态原样保留。底层详情与动作集合不变。不裁切、焦点圈定、Esc 正确。
Dark / reduced motion语义颜色保持；场景可换调色板。焦点、选择、离线不只靠颜色。无闪烁依赖，无低对比文字。
固定截图矩阵

1040×840 外窗下至少覆盖：中文/英文/日文 × 明/暗 × 庭院/卡片；另加空详情、单条 focused、批量、未解决副本、管理 Dialog、四个全局 Dialog 和最长真实字符串。
