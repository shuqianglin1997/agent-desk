# 猫有多忙、新回复、颜色标签：开发规划

> 状态：所有者已于 2026-11-24 看过可操作的预览页并批准方向（“可以，安排开发”）。
>
> 预览页：<https://claude.ai/artifact/4j2ediLpy6dez9Efo2SM32>。
>
> 本文是实施细化，不覆盖 `docs/PERSONAL_AGENT_MESH_PLAN.md`；动手前按 `AGENTS.md` 的规定把那份基准从头读完。

## 1. 要做的三件事

1. **猫有多忙**：一个账号同时在跑的对话越多，猫越忙，名牌上写“N 条在跑”。
2. **新回复**：对话回完了、人还没看过的，在列表里标出来，卡片上给出条数。
3. **颜色标签与筛选**：人给对话打五种标签之一，列表可以按标签和“新回复”筛选、排序。

三件事都只呈现 AgentDesk 确实知道的东西，不猜。

## 2. 不变的边界

- 会话表不变成任务队列（基准 6.3）：没有状态流转、截止时间、负责人，也没有“完成”。
- 应用不替人打标签、不排优先级、不写摘要（基准 5.2）。标签的含义完全由人自己定，默认名字只是颜色词。
- 列表的一行仍是一条逻辑会话（基准 7.9）：压缩检查点、子代理记录不单独计数，也不单独打标签。
- 渲染、筛选不得改变人的选择（基准 11.11 第 10 条）：标签筛选对“正在看的那一条”和“已勾选的那些”的处理，必须与现有搜索框完全一致，不另立规则。
- Renderer 不提交路径；新增的写入只走本文列出的专用 IPC，Main 重新校验。
- 标签和“看过”的记号只存在本机 AgentDesk 自己的数据里，不写进任何官方客户端的文件，本期不随 Mesh 同步。
- 新文案中、英、日三份词表的 key 必须一致；动效遵守 reduced-motion；标签不只靠颜色区分（每种另有形状）。

## 3. 猫有多忙

### 3.1 数的口径

- 现状：`src/activity.js` 的 `activeNow` 数的是“5 分钟内动过”的逻辑会话，卡片上 `account-card-busy` 用的就是它。这个口径太宽。
- 新增 `writingNow`：非归档的逻辑会话里，文件在最近 90 秒内有新内容的条数。90 秒与 `src/yard/cats.js` 的 `WORKING_WINDOW` 一致，两处共用一个常量。
- 同时返回这些会话的稳定键（与 `SessionTable.keyOf` 同一口径，上限 32 个），供列表给对应的行画“在跑”。
- 调度中枢的后台运行是准确的：`starting`、`running` 的运行按 `target.profileId` 计入。与文件口径可能重复时不相加，取两者中较大的。
- 一只猫（AgentIdentity）的条数是它本机各运行位置之和。远端位置没有这项数据时不计，也不显示 0 条。
- 刷新仍是现有的 8 秒一次。停着等人点允许的对话没有新内容，不算在内；这一点写进悬浮说明。

### 3.2 分档与呈现

| 条数 | 档 | 猫 | 名牌 |
|---|---|---|---|
| 0 | 不变 | 现有的状态判断 | 现有文案 |
| 1 | 干活 | 现有 `working` | 1 条在跑 |
| 2–3 | 忙 | `working` 加快；旁边一摞纸，一条一张；隔几秒一滴汗 | N 条在跑 |
| 4 及以上 | 抓狂 | 新动作：两只爪子轮流砸键盘，身体在 2px 格子上抖 1–2px，键帽和纸屑飞出，头顶“!!”或一团汽；纸摞高而歪 | N 条在跑 |

- “忙”“抓狂”是“干活”的加深，不改变既有的先后顺序（迷糊、干活、赶来先演；其次能量格；最后作息）。
- 两个新动作在 `src/pixel/cats.js` 里逐帧画，不用 CSS 拉伸和旋转。预览页里的抓狂是拿 `working` 的帧拼的，只作参考，正式的帧要单独画。
- 分档的两个界线（2 和 4）写成常量，便于以后调整。
- reduced-motion 下只显示静止姿势和条数。

## 4. 新回复

### 4.1 能知道什么

AgentDesk 看不到人在官方客户端里读没读。它只能知道三件事：最后一句是谁说的、这一轮回完没有、人有没有在 AgentDesk 里点开过这一行。所以叫“新回复”，不叫“未读”，界面和文档都不使用“未读”。

### 4.2 判断

- 扫描时为每条会话多记三样：`lastRole`（user / assistant / 未知）、`lastReplyAt`（最后一条助手消息的时间）、`replyDone`（这一轮是否回完）。
  - Claude 命令行：`claudeCliRecord` 已经在读文件末尾 64KB，从中取。
  - Codex：`lastEventTimestamp` 已经在倒读末尾 64KB，从 `response_item` 的 `payload.role` 取。
  - 两种格式里“回完”各用什么标志，由实现时对照真实文件确定；拿不准时退回“最后一句是助手，且 90 秒内没有新内容”。
  - 其他客户端要整篇解析才知道角色，本期一律“未知”，不标。远端会话同样不标。
- 一条会话算“有新回复”，当且仅当：`lastRole` 是助手、`replyDone` 为真、`lastReplyAt` 晚于这条会话的“看过时间”。
- “看过时间”在以下时刻更新为当时的 `lastReplyAt`：人在列表里点了这一行；人用了“全部标为已看”。从 AgentDesk 打开客户端不算看过。
- 人在客户端里接着说了，`lastRole` 变成 user，标记自然消失，不需要额外处理。
- 首次启用时记下一个起点时间，早于它的回复一律不标，避免把几百条旧会话全标出来。
- 正在跑的行显示“在跑”（三个点逐格走），回完之前不显示“新回复”。

### 4.3 呈现

- 行：标题加粗，标题前一个小气泡，标题后“新回复”小标。出现时播一次两帧的“冒出来”。
- 卡片：猫旁边一个信封加条数，名牌下一行“N 条新回复”；0 条时都不显示。点信封等于打开“新回复”筛选。
- 声音：用现有的“来了东西”。只在窗口不在前台时响，半分钟内最多一声；首次启用的起点之前的不响；服从现有的三档音量设置。

## 5. 颜色标签与筛选

### 5.1 标签

- 五种，固定顺序：红·方块、黄·三角、绿·圆点、蓝·菱形、紫·星。颜色取皮肤里读得清的 `*-ink` 一系，明暗主题都要过对比度。
- 一条会话最多一个标签。
- 打标签的四个入口：行上点右键；正在看的行右边的“标签”；选中一行后按 1–5，按 0 去掉；勾选多行后在动作坞里选，几行一起打。
- 选择器是五个形状加“不要标签”。
- 改名：双击筛选条里的形状，就地改，最长 12 个字。名字只在悬浮说明和选择器里出现，按数据处理并转义。

### 5.2 筛选与排序

- 筛选条在会话工具栏里、搜索框左边：一个“新回复 N”开关，加五个形状。点一下开，再点一下关。
- 几个形状同时开时，符合其中一个就显示；“新回复”与它们是“并且”。有筛选时出现“清除”，并显示“正在显示 4 / 10 条”。
- 筛选只是这一次看的方式，不记进稳定设置，重启后回到不筛选。
- 排序放进“显示”菜单：最近活跃（默认）、新回复在前、按标签。排序方式记进稳定设置。点表头排序的现有行为不变。
- “全部标为已看”也在“显示”菜单里。

### 5.3 存放

- 新模块 `src/session-marks.js`，数据在 `userData/session-marks.json`，原子替换写入。
- 内容：`tags`（会话键 → 1–5）、`seen`（会话键 → 看过时间）、`names`（五个名字）、`baselineAt`。
- 会话键用 `SessionTable.keyOf` 的结果。Main 校验长度、字符和数量；条目上限 5000，超出时先清最久没出现过的。
- 专用 IPC，全部只收会话键、1–5 的数字和有界字符串：`sessionMarks:get`、`sessionMarks:setTag`、`sessionMarks:markSeen`、`sessionMarks:rename`。不开放通用读写。

## 6. 分批

1. **数据**：`activity.js` 的 `writingNow` 与在跑的会话键；`sessions.js` 的三个新字段；`session-marks.js`、IPC、preload；对应的单元测试。
2. **列表**：行上的三种记号、筛选条、“显示”菜单的排序与“全部标为已看”、标签选择器与四个入口、改名、卡片上的信封与条数、声音；三语词表。
3. **猫**：`忙`、`抓狂`两个动作和纸摞、汗、键帽等小件；名牌改用新口径的条数；动作表的测试。
4. **收尾**：`docs/PRODUCT.md`、`docs/SCENARIOS.md`、`docs/INTERNAL.md`；隐藏窗口里走一遍真实界面；刷新验证记录。

每一批结束都要过 `npm test`、`npm run check`、`npm run check:docs`，然后把这一批提交到 `main`，再开始下一批：只暂存这一批自己的文件，不用 `git add -A`，不提交别的会话没做完的文件（见 `AGENTS.md` 的“Commit as you go”）。不开测试窗口、不启动客户端、不安装、不推送，除非所有者另外提出。

## 7. 没有定的

- 命令行（`docs/AI_INTERFACE.md`）要不要在只读的会话列表里给出标签和“新回复”两个字段。本期不做。
- 标签要不要随 Mesh 跟到其他设备。需要新的签名目录事件，另行评审。
- 其他客户端（Kimi、Gemini、Qwen、OpenCode）的“新回复”。要先确认读末尾就能判断角色。

## 8. 实施记录

### 第 1 批：数据（2026-11-24）

- `src/sessions.js`：Claude 命令行与 Codex 的每条会话多了 `lastRole`、`lastReplyAt`、`replyDone`，从已经在读的文件末尾 64KB 里取，没有多读文件。对照本机真实文件定下的“回完”标志：Claude 命令行是 assistant 事件的 `stop_reason` 为 `end_turn` 等结束值（`tool_use` 表示还在干，只装着 `tool_result` 的 user 事件是工具输出、不是人说的话）；Codex 是 `event_msg` 的 `task_complete`（推理、工具调用和输出都算这一轮还没完，`turn_aborted` 是人打断了，不算回完）。拿不准时 `replyDone` 为 `null`，按“最后一句是助手且 90 秒内没有新内容”退回判断。
- `src/activity.js`：新增 `writingNow` 与 `writingKeys`（上限 32），窗口直接用 `src/yard/cats.js` 导出的 `WORKING_WINDOW`。“有新内容”对追加型的 `.jsonl` 看文件长度变没变，不看 mtime，因为客户端会无故 touch 文件；第一次见到的文件和整文件重写的 `.json` 只能信 mtime。已经知道这一轮回完的会话不算在跑（回完后客户端还会补写几行收尾记录）。Cursor 这类数据库型客户端没有给出在跑条数时为 `null`，不当 0。子代理的 Claude 命令行文件不计。
- “新回复”在主进程的活动探测里判断，而不是在列表里：活动探测 8 秒一轮、覆盖所有本机运行位置，所以没有加载到列表里的猫，卡片上也能给出条数。只读首次启用之后动过的文件或正在写的文件的末尾，并按文件版本缓存。判断规则在 `src/session-marks.js` 的 `freshReplyAt`，与第 4.2 节一致。
- 会话键：`src/session-table.js` 新增 `markKeyOf`。本机扫到的会话用 `keyOf` 的本机口径“运行位置::会话地址”，只有别的设备上的会话用 `mesh::逻辑会话`。这样开没开设备网、密钥延后时退回本机扫描，同一条会话的键都不变，主进程也能算出同一个键；在没有开设备网时它与 `keyOf` 完全相同。后台对话的行没有键。
- `src/session-marks.js` 与 `userData/session-marks.json`：每条会话一项 `{ tag, seen, at }`，`at` 是最后一次动它的时间。超过 5000 条时先清最久没动过的“看过”记号，人亲手打的标签排在后面才清。四个 IPC 只收会话键、0–5 的整数（0 去掉标签）、时间数字和最长 12 个字的名字。

### 第 2 批：列表（2026-11-24）

- 行上：最前面是标签的形状，然后是新回复的小气泡或在跑的三个点（逐格走），标题后面是“新回复”或“在跑”小标；新回复的标题加粗。点阵字没有粗体，皮肤又规定“不描粗”，所以这里是唯一的例外：横向多描一格（字的一个像素）。正在看的、指着的、焦点在里面的那一行露出“标签”按钮。
- 打标签的四个入口都在：右键一行、那一行的“标签”、选中一行后按 1–5（0 去掉）、勾选几行后在动作坞里点“打标签…”。按键只在焦点在会话面板里（或没有焦点）、没有打开的弹窗、不在输入框里时生效。这一行已勾选时，标签打给全部勾选的，和“复制会话信息”的范围一致。
- 选择器是一个进浏览器顶层的 popover（`#sessionTagPicker`），五个形状加“不要标签”，方向键可选，按数字直接选。
- 筛选条在搜索框左边。筛选和搜索在 `applySessionFilter` 的同一处生效，只决定哪些行显示，正在看的和已勾选的原样不动；被筛掉的勾选项和搜索一样在顶栏提示。点一下筛选不能让筛选条挪位置（否则双击的第二下会落到旁边的形状上）：整组控件靠右，“清除”不出现时也占着位置，条数一直留出“N / N”的宽度。除了双击，形状获得焦点时按 F2 也能改名。
- 工具栏只有一行。中文放得下全部；英文、日文、或勾选了几行时放不下，就按顺序收起：先收起“新回复”三个字（留气泡和条数），再让“打开目录”“导出”“送出”只留图标（提示和读屏文字都在），“复制会话信息”始终带字。由 `fitSessionToolbar` 每次渲染时量过再定。
- 卡片：信封在猫的左上方，带条数，点它就选中这只猫并只看它的新回复（同时清掉标签筛选）。“N 条新回复”没有另起一行，而是接在名牌状态那一行的后半段：Agent 区是定死的 222px，卡片底边原本在 267px、名册在 280px 处裁掉，多一行（16–18px）会把“打开”“档案”挤到搁板下沿以外。
- 声音：主进程报来的新回复比上一轮多了，renderer 发出 `agentdesk:replies`，声音层只在窗口不在前台时响“来了东西”，半分钟内最多一声。窗口最小化或被完全挡住时浏览器把页面标成隐藏，现有规矩是隐藏时不做 8 秒一轮的探测，所以那时不会响，回到前台的第一轮探测把它当作已经在那儿的回复。
- 标签颜色：浅色 `#B5383A`、`#9A6508`、`#3F7F3E`、`#2F6AA0`、`#7B4FA6`，夜间沿用预览页那一组。形状是图形，测试按 3:1 核对纸、桌面、选中、勾选四种底色。浅色的黄比预览页里的深一档，因为预览页那一档在选中的底色上只有 2.5:1。

### 第 3 批：猫（2026-11-24）

- `src/yard/cat-art.js` 多了两个循环动作。忙：干活的帧加快到每秒 9 帧，左边一摞纸，28 帧（约 3 秒）里有 3 帧额头冒汗往下流。抓狂：12 帧、每秒 12 帧，两只爪子轮流砸键盘，眼睛瞪圆，键帽和纸屑往外飞，前 6 帧头顶两个叹号，后面冒一团汽，额头一直冒汗。新加的小块是爪子、键帽、纸屑、两种汽和一张纸，都画在原来那只坐着的猫上；批准的十九个动作一格没动，`test/pixel-cats.test.js` 仍逐格对着批准的原件核对它们，新动作另有自己的测试。
- 纸摞的张数等于同时在跑的对话数，由 `frame()` 的 `options.papers` 给出（忙最多 3 张，抓狂最多 7 张，第 5 张起歪过去，最上面那张晃），所以不用为每个张数各做一个动作。
- 计划里写“身体在 2px 格子上抖 1–2px”。卡片上一格是 4px，按整格抖就是 4px，所以抖动写在帧的 `nudge` 里，单位是半格，由放映机画的时候加上；格子本身不变，最多偏 2px，落在 2px 的格子上。抖的是整幅画（猫、电脑、纸一起）。
- 分档在 `src/yard/cats.js`：`BUSY_AT = 2`、`FRANTIC_AT = 4`、`busyAction(count)`；忙与抓狂和干活一样排在最前一档（迷糊照旧先演）。
- 名牌：有在跑的对话时，状态那一行写“N 条在跑”，悬浮说明写明停着等人点允许的不算；原来名字后面按 5 分钟口径算的“×N”去掉了，不再有两个口径。条数是本机探测的 `writingNow` 与调度中枢正在跑、目标是这只猫的段数两者取大；都不知道时不显示，也不显示 0 条。0 条时照旧用原来的状态判断，所以一条对话刚回完的那 90 秒里，猫可能还演着干活、行上却已经是“新回复”，这是计划第 3.2 节“0 条不变”的结果。
- 有一处与原来的判断不同：原来进程探测说客户端没开（命令行客户端常常探测不到）时，近期写入只算残留、不算干活；现在只要探测到文件在长、这一轮还没回完，就按条数演干活、忙或抓狂。
- 给所有者看的帧：https://claude.ai/artifact/2rEJ4KDeXCknyKJ7PgbzCF（实际大小与两倍大小，正常与夜间）。
